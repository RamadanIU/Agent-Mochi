# Мочи · облачный агент

Пиксельный зверёк-помощник, который живёт на твоём сервере и работает в настоящем Linux:

* **агент работает в фоне** — закрыл браузер, а задача идёт; вернулся — видно прогресс или итог;
* **терминал** сервера прямо в браузере (ttyd + tmux);
* **проводник** по файлам сервера (с правами агента, при полном доступе — и root);
* **вход** по приглашению, **Telegram** — управление и уведомления.

> Браузерной версии (Linux в эмуляторе v86 на GitHub Pages) больше нет — Мочи работает только на сервере.

---

## Установка на сервер — одна команда

```bash
curl -fsSL https://raw.githubusercontent.com/RamadanIU/Agent-Mochi/HEAD/install.sh | sudo bash
```

Установщик сам:

1. определяет ОС, архитектуру и систему инициализации (Ubuntu/Debian, Fedora/RHEL/Rocky/Alma, Alpine, Arch, openSUSE; x86_64, arm64, armv7; systemd или OpenRC);
2. ставит пакеты, **Node.js 22**, **ttyd 1.7.7** и **Caddy 2.10** — с проверкой контрольных сумм;
3. заводит отдельных системных пользователей и службы;
4. получает HTTPS-сертификат Let's Encrypt — для своего домена или для адреса вида `1-2-3-4.sslip.io` (если домена нет);
5. печатает ссылку для первой регистрации:

```
  Открой и зарегистрируйся (первый пользователь станет администратором):
    https://203-0-113-7.sslip.io/?invite=k3x9-p2mf-q8wd
```

Дальше: **Настройки → Модель** — провайдер (OpenAI, OpenRouter, Ollama Cloud, JustWoker, LM Studio или «Другой» — любой OpenAI-совместимый адрес, например свой Ollama `http://localhost:11434/v1`) и ключ. Ключ хранится на сервере и в браузер не возвращается.

Там же — **«Ограничение шагов»**: сколько шагов подряд (вызовов модели без твоих новых сообщений) Мочи делает в одной задаче, прежде чем остановиться, чтобы не зациклиться (по умолчанию 100 — меняется переменной `MOCHI_MAX_STEPS` в `/etc/mochi/mochi.env`). Число можно поменять (от 1 до 10 000), а ограничение — выключить совсем: тогда Мочи работает, пока не закончит или пока не нажмёшь «Стоп».

### Параметры

```bash
curl -fsSL https://raw.githubusercontent.com/RamadanIU/Agent-Mochi/HEAD/install.sh | sudo bash -s -- --domain mochi.example.com --email me@example.com
```

| Параметр | Что делает |
|---|---|
| `--domain NAME` | свой домен (A-запись → этот сервер) |
| `--email ADDR` | почта для Let's Encrypt |
| `--no-tls` | без HTTPS: Мочи слушает только `127.0.0.1:8787`, вход через SSH-туннель `ssh -L 8787:127.0.0.1:8787 сервер` |
| `--no-tls --public-url https://…` | свой обратный прокси (nginx и т. п.) перед `127.0.0.1:8787`, с поддержкой WebSocket |
| `--root` | полный доступ агента: root через `sudo` без пароля (то же — `--with-sudo`; потом переключается в настройках, см. «[Полный доступ агента](#полный-доступ-агента-root)») |
| `--no-root` | забрать у агента root (то же — `--no-sudo`). Без этих флагов повторная установка и `--update` оставляют доступ как был |
| `--update` | обновить код и зависимости, сохранив настройки и данные (то же — `sudo mochi update` или кнопка в настройках) |
| `--uninstall [--purge]` | удалить (с `--purge` — вместе с данными) |

Нужны открытые порты **80 и 443** (у многих хостеров есть ещё облачный firewall в панели). Требования: 1 ГБ RAM, systemd или OpenRC.

### Управление

```bash
sudo mochi invite        # ссылка-приглашение для нового пользователя
sudo mochi users         # пользователи
sudo mochi passwd ИМЯ    # сбросить пароль (новый будет напечатан)
mochi status             # состояние служб
mochi logs               # журнал
sudo mochi restart
sudo mochi update        # обновить (то же — кнопка в настройках)
sudo mochi root on       # полный доступ агента (root); off — забрать, без слова — показать состояние
```

### Обновление

Обновлять можно прямо из браузера. Мочи сама раз в 6 часов смотрит на GitHub, вышло ли что-то новое, и если да — администратору при входе выскакивает окошко с питомцем: «Ура! Вышло обновление!», список изменений и кнопки **«Позже»** / **«Обновить»**. «Позже» — напомнит через сутки (или когда выйдет следующая версия); на шестерёнке настроек горит точка.

То же вручную: **Настройки → Сервер → Обновления** — какая версия стоит, «Проверить обновления», «Обновить».

После «Обновить» Мочи показывает ход работы (шаги установщика и полоску), сервер перезапускается примерно на минуту, страница сама перезагружается уже с новой версией. Переписка, настройки и файлы сохраняются, начатые задачи агента продолжаются сами. Если что-то пошло не так — видно, на каком шаге, и можно нажать «Повторить» (установщик безопасно запускать повторно). Остальные открытые вкладки и устройства перезагрузятся сами, когда увидят новую версию сервера.

Как это устроено:

* **Что стоит.** Установщик кладёт рядом с кодом `build.json`: репозиторий, ветку и точный коммит (GitHub пишет его в заголовок архива с кодом).
* **Что нового.** Сервер сравнивает этот коммит с последними коммитами той же ветки через API GitHub (с ETag: повторная проверка не тратит лимит) или, если лимит API в 60 запросов в час исчерпан (бывает на общем IP хостинга), — через ленту `github.com/…/commits.atom`. В окошке — названия изменений (у слияний PR — название PR).
* **Обновить.** Сам сервер обновиться не может: он работает без прав root. Поэтому кнопка только кладёт файл-запрос в данные сервера, а его замечает отдельная root-служба (`mochi-update.path` в systemd, `mochi-updater` в OpenRC) и запускает `server/bin/mochi-update`. Тот берёт **свои** настройки (`/etc/mochi/install.conf`: репозиторий и ветку), узнаёт точный последний коммит, скачивает `install.sh` и код ровно этого коммита и запускает `install.sh --update`. Из запроса не берётся ничего — даже взломав сервер Мочи, нельзя подсунуть другой код или старую версию.
* **Ход работы** — в `/var/lib/mochi/update`: `status.json` и `steps.log` (только строки шагов) читает сервер, полный журнал `install.log` — только root.

> **Если Мочи стоит давно** (до появления этой кнопки): один раз обновись вручную — `sudo mochi update`. Эта команда поставит службу обновления, дальше хватит кнопки.

### Полный доступ агента (root)

По умолчанию агент работает как обычный пользователь `mochi-agent`: свои папки, пакеты Python и npm — к себе, без `sudo`. Если Мочи должна администрировать сервер — ставить системные пакеты, настраивать nginx, Docker и службы, править `/etc`, — дай ей полный доступ:

* **Настройки → Сервер → «Доступ агента» → «Дать полный root»** — только администратор и только с подтверждением паролем. Забрать — там же, одной кнопкой;
* или на сервере: `sudo mochi root on` / `sudo mochi root off` / `sudo mochi root` (что сейчас);
* или сразу при установке: `… | sudo bash -s -- --root`.

Что меняется:

* `mochi-agent` получает `sudo` без пароля — правило `/etc/sudoers.d/mochi-agent`, проверенное `visudo`. Под sudo umask `0022`, поэтому файлы в `/etc` и `/var/www` читаются службами. В `PATH` есть Node.js Мочи, а `DEBIAN_FRONTEND` и похожие переменные сохраняются, так что `apt` и `pip` не задают вопросов. Если sudo не понимает этих настроек (например, `sudo-rs`), пишется только само правило.
* С исполнителя команд и терминала снимается изоляция systemd — drop-in `mochi-runner.service.d/mochi-root.conf` и такой же для `mochi-term`. С `NoNewPrivileges`, `ProtectSystem` и прочими ограничениями sudo не работает. Сами службы в установщике по-прежнему изолированы: убери drop-in — и изоляция вернётся.
* **Файловые инструменты** (`read_file`, `view_image`, `edit_file`, `write_file`) сначала работают от `mochi-agent`. Если прав не хватило, они повторяют то же от root (`sudo node mochi.js fileop`). Агент правит `/etc/nginx/nginx.conf` так же, как свои файлы; владелец и права чужих файлов сохраняются, а в ответе отмечено «сделано от root».
* Агент знает о root из системной подсказки. Системное он делает через `sudo`, перед необратимым (удаление данных, переустановка, настройки SSH и firewall) спрашивает, а службы Мочи без просьбы не трогает. Без root он подскажет, где его включить.
* **Терминал**: в строке состояния — `[мочи·root]`, root-оболочка — `sudo -i`.
* Доступ переживает обновления и повторную установку (`/etc/mochi/install.conf`).

Как это устроено. У сервера Мочи нет прав, поэтому он только кладёт файл-запрос. Из запроса берётся одно слово, `on` или `off`, больше ничего. Запрос забирает root-служба: `mochi-access.path` в systemd или `mochi-updater` в OpenRC. Она запускает `server/bin/mochi-access`, и тот:

1. пишет правило и drop-in;
2. перезапускает исполнитель и терминал — идущие команды обрываются, агент это видит и продолжает;
3. проверяет, что sudo действительно работает;
4. пишет итог в `/var/lib/mochi/update/access.json`, который показывают настройки.

Если ничего не поменялось, службы не перезапускаются. При выключении служба проверяет, не осталось ли у `mochi-agent` прав root из чужих правил sudo или групп (`sudo`, `wheel`, `docker`…), и предупреждает о них. Переключение и обновление не идут одновременно: у них общий замок. Если агент (или кто-то в терминале Мочи) сам выполнит `sudo mochi update`, `sudo mochi restart` или `sudo mochi root off`, команда не оборвёт себя на полпути — она уйдёт через root-службу.

> **Осторожно.** Root получает **каждый** пользователь Мочи: агент и терминал у всех общие. А prompt injection — инструкция, спрятанная на сайте или в файле, который прочтёт агент, — сможет управлять всем сервером, в том числе прочитать ключи API и пароли Мочи. Включай root, только если доверяешь всем пользователям и сервер не жалко. Выключение забирает sudo, но всё, что агент успел поменять в системе, остаётся.

## Как это работает

```
 браузер / телефон ──HTTPS──▶ Caddy :443 ──▶ Мочи-сервер 127.0.0.1:8787 (пользователь mochi)
                                               │  ├─ вход, сессии, чат, SSE-поток событий
                                               │  ├─ агент (цикл модели) и Telegram-бот
                                               │  └─ прокси /term/ (только после входа)
                                               │
                 unix-сокеты (группа mochi) ───┼──▶ mochi-runner  — выполняет команды агента
                                               └──▶ ttyd + tmux   — терминал     (пользователь mochi-agent)
```

* **Фоновая работа.** Задача живёт на сервере. Чат в браузере только подписывается на поток событий (`/api/stream`): закрыл вкладку — работа идёт; открыл — видишь все шаги и итог. Состояние на диске, поэтому даже перезапуск сервера не теряет задачу: она продолжится сама.
* **Сообщения во время работы.** Пока Мочи работает, писать можно как обычно (Enter или кнопка «Отправить»; рядом появляется отдельная кнопка «Стоп»). Сообщение не отклоняется, а ждёт над полем ввода и уходит модели в ближайшей паузе между шагами — после текущей команды или ответа модели — с пометкой «во время работы»: модель понимает, что это дополнение, новая просьба или вопрос по ходу дела, учитывает его и продолжает задачу, а на вопрос отвечает сразу. Пришло, пока модель дописывала итоговый ответ, — она ответит и на него в той же задаче.
  * **«Прочитать сейчас»** — не ждать конца шага: долгая команда или ответ модели прерываются, и модель читает сообщения немедленно (задача продолжается).
  * **«X»** у сообщения — отозвать, пока модель его не прочла: текст (и вложения) вернутся в поле ввода.
  * Лимит шагов считается от последнего твоего сообщения: дописал по ходу — счётчик начинается заново.
* **«Стоп» — мгновенно.** Агент больше не ждёт, пока прерванная операция закончится: команда, которая не реагирует на SIGTERM (apt, сборки, `sudo`), раньше держала «Стоп» до SIGKILL (3 с), а подключение к MCP-серверу или поиску — до 10–30 с. Теперь задача останавливается сразу (десятки миллисекунд), а исполнитель добивает процесс в фоне. Кнопка откликается без ожидания потока событий: сервер отвечает на «Стоп», когда задача уже остановлена. Сообщения, которые модель не успела прочесть, остаются в переписке, а под отметкой «Остановлено» — кнопка «Продолжить»: Мочи ответит на них.
* **Экран загрузки.** Пока Мочи просыпается, её окошко показывает «BIOS» с шагами — страница, сервер (пинг), вход, модель, чат (сколько сообщений), агент (свободна или работает), — сколько занял каждый шаг и сколько осталось ждать. Прогноз — по прошлым загрузкам на этом устройстве (медиана пяти последних по каждому шагу), в первый раз — по скорости сети, которую знает браузер. Шаг затянулся — объясняет почему; сервер не отвечает (перезапуск, обновление, пропала сеть) — говорит об этом, сама повторяет попытки с обратным отсчётом и продолжает, как только сервер вернётся. Если в этот момент Caddy отвечает 502, страница берётся из кэша, а когда сервер проснётся — обновляется сама. Итог каждой загрузки — в консоли браузера («Мочи: загрузка 1,2 с …»).
  * Страница лёгкая — ~160 КБ в сжатом виде (раньше в ней был целый Linux для браузерной версии, 3,8 МБ): на сети 4 Мбит/с Мочи готова меньше чем за секунду, а не через 9.
  * Длинная история: сначала рисуются последние 100 сообщений, раньше — по кнопке «Показать раньше» или когда долистаешь до неё; позиция при этом не прыгает. 400 записей с таблицами и кодом на слабом телефоне рисовались ~4 с, теперь ~1 с.
  * Поиск в интернете (MCP) сервер подключает сразу при старте и не ждёт его дольше 2,5 с: раньше первое сообщение после перезапуска ждало подключения к поиску, а если поиск не отвечал — до 10 с.
* **Терминал.** Вкладка «Терминал» — настоящий shell сервера в tmux: можно закрыть браузер, а запущенное продолжит работать. Команды агента видны прямо в нём: Мочи «печатает» команду (с меткой `МОЧИ`) и выводит её результат, а потом возвращает твоё приглашение вместе с недонабранной строкой. Если в терминале открыта твоя программа (vim, top…), агент её не перебивает. Кнопки Esc/Ctrl+C/Tab/стрелки и строка ввода удобны на телефоне.
* **Файлы.** Прикреплённое в чате попадает в `~/ИМЯ/inbox/`, результаты агент отдаёт через `send_file` — в чате появляется кнопка «Скачать». Всё остальное — во вкладке «[Файлы](#файлы-проводник)».
* **Работа с кодом и текстом.** Файлы агент читает и правит своими инструментами, а не через `cat`/`sed`/heredoc: так нет проблем с экранированием, тихих «ничего не заменилось» и случайно стёртых файлов. Поиск, запуск, сборка и git — по-прежнему через `run_command`.
  * `read_file` — строки с номерами, срезы (`offset`/`limit`, отрицательный `offset` — хвост лога) и подсказка, откуда продолжить; вывод ограничен (~40 тыс. символов), длинные строки обрезаются, двоичное не выводится. Тот же кусок той же версии файла повторно не выводится — модель получает короткую отсылку к уже прочитанному.
  * `view_image` — агент сам смотрит на картинку с сервера (фото, скриншот, график): PNG, JPEG, GIF или WebP до 8 МБ, формат определяется по байтам, а не по расширению. Результат инструмента у OpenAI-совместимых API бывает только текстом, поэтому картинка уходит модели следующим сообщением — как вложение пользователя. Нужна модель со зрением; если модель картинки не принимает или зрение выключено в настройках, инструмент так и отвечает. Другие форматы (SVG, PDF, HEIC) агент сначала конвертирует в PNG командой. `read_file` на картинке подсказывает `view_image`.
  * `edit_file` — замена точного фрагмента `old_string` → `new_string`, который обязан встречаться один раз (или `replace_all`). Несколько правок файла — одним вызовом (`edits`): по порядку, все или ни одной. Если фрагмент не найден, модель видит самое похожее место с номерами строк; если правка уже сделана — так и сказано. Прощаются частые ошибки: номера строк, скопированные из `read_file`, и расхождения только в пробелах по краям строк (отступы новой версии подгоняются под файл). В ответе — изменённые строки с соседними, перечитывать файл не нужно.
  * `write_file` — создать файл (с папками) или заменить целиком. Непустой существующий файл перезаписывается, только если агент читал именно эту его версию (не изменённую потом командой).
  * Общее: запись атомарная (временный файл + `rename`), сохраняются права, окончания строк CRLF, BOM, симлинки и жёсткие ссылки; файлы не в UTF-8 не портятся. Заглушки вместо кода («`// ... остальное без изменений`») не дадут стереть настоящий код — пропускаются, только если модель повторит тот же вызов. После записи JSON, JS, Python и shell быстро проверяются на синтаксис, и модель получает предупреждение — но только если сломала именно эта правка.

## Файлы (проводник)

Третья вкладка — «Файлы»: файловая система сервера в виде окна старого компьютера. Полосатый заголовок с названием папки, строка «12 объектов · 1,4 МБ · свободно 10 ГБ», как в старом Finder, а внутри — папки и файлы **сеткой** из пиксельных значков 24×24 (или списком на «зелёнке», как распечатка старого принтера). Цвета значков — из выбранной темы: розовые папки у «Для девочек», голубые у «Для мальчиков», янтарные у «Ламповой»; в тёмной теме — те же, только приглушённые.

* **Папки** открываются двойным щелчком (на телефоне — касанием): значок раскрывается, и из него в окно «вылетают» пунктирные рамки — та самая анимация из старых систем. «Наверх» — рамки сворачиваются обратно в папку, из которой пришёл, и она мигает. У особых папок свои значки: дом, входящие и исходящие, навыки (сердечко), код, фото, музыка, видео, `/etc`; корень `/` — жёсткий диск.
* **Значки по типу файла**: картинка, видео, музыка, код, текст, Markdown, таблица, PDF, архив (с молнией), шрифт, программа (экранчик `>_`), настройки (шестерёнка), ключи, образы дисков, двоичное (`0101`). Ссылки — со стрелкой и курсивом, битые — с красным крестиком; скрытые — бледные. У картинок — миниатюры в рамке (пиксель-арт увеличивается без размытия).
* **Навигация**: назад/вперёд/наверх, «крошки» пути (щелчок по пустому месту — ввести путь, `~` — домашняя папка), «Места» (своя папка, inbox/outbox, навыки, папка агента, корень, `/tmp`, `/etc`, `/var/log`), поиск — набор сразу отбирает в текущей папке, Enter ищет по всем вложенным (`*.jpg`, `report?.txt`). Сортировка по имени, размеру, дате, типу; три размера значков; скрытые файлы — по желанию. Последняя открытая папка запоминается. Пока вкладка открыта, папка обновляется сама: если Мочи создала файл, он тут же появится.
* **Выделение**: щелчок, Ctrl/Shift, рамка «бегущие муравьи» по пустому месту; на телефоне — долгое касание, дальше касаниями. Снизу — панель действий.
* **Действия**: открыть, скачать (папку — архивом `.tar.gz`), копировать/вырезать/вставить, дублировать, переименовать прямо в подписи (F2), новая папка/файл, удалить (с подтверждением — корзины нет), сжать в `.tar.gz`, распаковать ZIP и tar-архивы, «Свойства» (размер, в том числе папки целиком, даты, владелец, права с галочками `rwx`), копировать путь, «Открыть в терминале» (вкладка «Терминал» сразу переходит в папку), **«Спросить Мочи»** — путь вставляется в чат, осталось написать, что сделать.
* **Загрузка**: перетащи файлы или целые папки в окно (или на значок папки), либо «Загрузить файлы/папку» в меню. Окошко «Копирование» с полосой и скоростью, отмена; одинаковые имена — «Заменить» или «Оставить оба». Значки можно перетаскивать в папки, «крошки» и «Места» (с Ctrl/Alt — копировать).
* **Клавиатура**: стрелки, Home/End, Enter — открыть, Backspace / Alt+↑ — наверх, Alt+←/→ — назад/вперёд, Пробел — быстрый просмотр, F2, Delete, Ctrl+A/C/X/V/D, Ctrl+I — свойства, Ctrl+Shift+N — новая папка, Ctrl+F — поиск, F5, первые буквы имени — перейти к файлу, Shift+F10 — меню.

**Просмотр** — окно поверх папки, тоже с полосатым заголовком; ←/→ (или Alt+←/→) листают соседние файлы того же вида:

| Что | Как открывается |
|---|---|
| Картинки (PNG, JPEG, GIF, WebP, AVIF, BMP, ICO, SVG…) | на «шахматке», вписать / 1:1 / колесо и щипок — зум, перетаскивание, свайп — соседние; маленькие увеличиваются чётко по пикселям |
| Видео (MP4, WebM, MOV, MKV, OGV) | свой пиксельный пульт: перемотка (с подгрузкой кусками — `Range`), громкость лесенкой, скорость, по кругу, весь экран и режим «ЭЛТ» — строки развёртки старого телевизора; клавиши Пробел/K, ←/→, J/L, M, F, 0–9 |
| Музыка (MP3, OGG, Opus, WAV, FLAC, M4A, AAC) | кассетный плеер: катушки крутятся, название — на наклейке, спектр из «лампочек» как на музыкальном центре, список песен из папки, следующая включается сама |
| Текст и код | экранчик с номерами строк и подсветкой (JS/TS, Python, shell, C/C++, Go, Rust, Java, PHP, SQL, YAML, JSON, HTML, CSS, Dockerfile, ini/conf…), логи — ошибки красным, предупреждения жёлтым; перенос строк, «красивый» JSON, кодировки UTF-8/UTF-16/CP1251. **Правка** прямо здесь: Ctrl+S — сохранить, Tab — отступ; концы строк CRLF и BOM сохраняются, а если файл тем временем поменяли (например, Мочи), будет вопрос, а не тихая перезапись |
| Markdown, CSV, HTML | «Просмотр»: Markdown — тем же оформлением, что ответы Мочи (относительные картинки и ссылки на другие файлы работают), CSV — таблицей, HTML — страницей в песочнице без скриптов |
| PDF | встроенным просмотрщиком браузера (где его нет — открыть в новой вкладке или скачать) |
| Шрифты (TTF, OTF, WOFF, WOFF2) | алфавиты и «Съешь же ещё этих мягких французских булок» разными размерами |
| Архивы (ZIP, tar, tar.gz/xz/bz2) | что внутри (пути, размеры, даты) и «Распаковать сюда» |
| Всё остальное | HEX — как в старом дисковом редакторе, «как текст», скачать |

Как это устроено:

* **Права.** Проводник работает через исполнитель команд — от имени `mochi-agent`, ровно с теми же правами, что агент и терминал; данные сервера Мочи (`/var/lib/mochi/data`) ему недоступны. При [полном доступе](#полный-доступ-агента-root) то, на что прав не хватило (`/root`, `/etc/shadow`…), повторяется от root (`sudo node mochi.js fsop|fsget|fsput`), а в заголовке окна загорается `ROOT`. Корень, папки верхнего уровня (`/etc`, `/usr`…) и домашнюю папку агента нельзя удалить или унести — даже от root.
* **Байты** идут отдельным соединением с исполнителем: строка-заголовок JSON, дальше сырые данные — без base64 и без чтения файла в память. Отдача — с `Range` (перемотка видео) и `ETag`; загрузка — потоком во временный файл рядом, потом под своё имя (`link()` — без перезаписи), оборванная загрузка удаляется.
* **Безопасность страницы.** Файлы с сервера никогда не исполняются: ответы `/api/fs/raw` — с `nosniff` и CSP `sandbox` без скриптов, HTML и прочее неизвестное — как `text/plain` или скачиванием, SVG — только картинкой. Предпросмотр HTML — в `<iframe sandbox>` без скриптов. Изменяющие запросы — с той же защитой от CSRF, что и всё API.
* **Архивы**: ZIP разбирается самим сервером (центральный каталог, deflate через zlib) — `unzip` не нужен; tar — системным `tar`. Пути с `..` пропускаются, ведущий `/` отрезается, символические ссылки из ZIP не создаются.
* **Размер загрузки** — до 4 ГБ на файл (`MOCHI_MAX_UPLOAD_MB` в `/etc/mochi/mochi.env`).
* **API**: `GET /api/fs/info|list|stat|search|du|archive`, `GET|HEAD /api/fs/raw` (`dl=1` — скачать), `GET /api/fs/tar` (папка архивом), `PUT /api/fs/upload?dir=&name=[&over=1]`, `POST /api/fs/op` (`mkdir`, `newfile`, `rename`, `copy`, `move`, `delete`, `chmod`, `write`, `extract`, `pack`).

### Подключение к API модели

* **Запросы к модели** (`/chat/completions`, `/models`) делает сам сервер из Node.js — CORS к ним не применяется, подходит любой OpenAI-совместимый адрес. Свой Ollama или LM Studio на том же сервере — «Другой» и `http://localhost:11434/v1` (Ollama) или `http://localhost:1234/v1` (LM Studio).
* **Проверка в настройках.** Кроме `/models`, сервер шлёт пустой запрос к `/chat/completions` (без модели и сообщений — ничего не запускается, токены не тратятся): так видно, подходит ли ключ там, где `/models` открыт всем, и не закрыл ли Cloudflare запросы к модели.
* **Ollama Cloud** (`https://ollama.com/v1`) — ключ — на [ollama.com/settings/keys](https://ollama.com/settings/keys). Список моделей открыт и без ключа, поэтому без ключа Мочи пишет «Вставь API ключ».
* **JustWoker** (`https://api.justwoker.icu/v1`) — шлюз New API, ключ вида `sk-…` из его панели. Перед ним Cloudflare, который может блокировать запросы к модели с некоторых IP (например, сетей хостинга), хотя список моделей отдаёт. Тогда Мочи так и пишет — «Это не ключ: Cloudflare … заблокировал запрос» с Ray ID для поддержки; помочь может только владелец шлюза или другой сервер.
* **Cloudflare.** Если API отвечает страницей блокировки Cloudflare, Мочи один раз повторяет запрос через `curl` (так проходит OpenRouter) и, если не помогло, показывает понятную ошибку вместо «ключ не подошёл».

## Интерфейс

Всё приложение — в пиксельном ретро-стиле, в трёх темах («Для девочек», «Для мальчиков», «Ламповая»), каждая — светлая и тёмная по настройке системы.

* **Значки** нарисованы на одной сетке 10×10 и показываются в целое число раз крупнее — без размытия на любом экране. У кнопок есть подписи-подсказки, у вкладок снизу и разделов настроек — значки рядом с названием.
* **Объём**: кнопки выпуклые (блик сверху, «ступенька» снизу, при нажатии проседают), поля ввода — утопленные, облачка и карточки отбрасывают жёсткую пиксельную тень.
* **Настройки** разложены по карточкам: «Внешний вид», «Звук и голос», «Приложение», «Подключение», «Возможности», «Шаги агента». Темы показаны в своих цветах — сразу видно, как будет выглядеть.
* **Анимации** плавные: облачко «выдувается» из хвостика, окна мягко открываются и закрываются, подсветка вкладок и переключателей переезжает к выбранному. Перерисованная история (после переподключения) не анимируется заново. Если в системе включено «Уменьшить движение», анимаций нет.
* **Значок приложения** — пиксельный ламповый компьютер с тёплым янтарным экраном (`icons/`, для Android — версия `maskable` с безопасными полями).

## Оформление ответов

Ответы Мочи показываются с полноценной разметкой в том же пиксельном стиле, что и всё приложение. Всё рисуется своим кодом прямо на странице, без внешних библиотек, поэтому работает офлайн и под строгой CSP сервера.

| Что | Как выглядит |
|---|---|
| Заголовки, **жирный**, *курсив*, ~~зачёркнутое~~, ==выделение==, `<kbd>` | надписи как в старой игре |
| Списки (вложенные, нумерованные, с галочками `- [x]`) | пиксельные маркеры и чекбоксы |
| Таблицы | «ведомость» с полосками, числа по правому краю, кнопка «копировать» (для вставки в Excel) |
| Цитаты и врезки `> [!NOTE]`, `> [!TIP]`, `> [!WARNING]`, `> [!CAUTION]` | окошки с цветной полосой |
| Код с языком | экранчик с подсветкой цветами старого монитора, `diff` — зелёным и красным |
| Формулы LaTeX: `$…$`, `$$…$$`, `\(…\)`, `\[…\]` | дроби, корни, суммы, матрицы, `cases` — на листке в клетку |
| Схемы ` ```mermaid `: flowchart, sequenceDiagram, stateDiagram, pie, mindmap, timeline, а также ` ```dot ` | пиксельный SVG на миллиметровке, кнопка «код» показывает исходник |
| Сноски `[^1]`, источники `[1]: https://…`, `<details>`, картинки | значки-номера, раскрывашки, картинка или ссылка, если её не пускает CSP |

Модель знает об этих возможностях из системной подсказки и пользуется ими, когда это уместно: сравнение показывает таблицей, процесс — схемой. Ответ перерисовывается по мере печати, недописанная схема видна как код с подписью «рисую…».

## Telegram

Самый простой путь — попросить Мочи в чате: **«подключи Telegram»**. Мочи объяснит, как создать бота у [@BotFather](https://t.me/BotFather), примет токен (инструмент `telegram_connect`) и пришлёт одноразовую ссылку `t.me/твой_бот?start=…` — открой её и нажми «Старт». Токен сразу вычищается из истории чата и хранится только в защищённых данных сервера.

То же можно сделать в **Настройки → Сервер**.

В Telegram:
* обычное сообщение, фото или файл — новая задача (ход работы — в одном обновляемом сообщении); во время работы — дополнение или вопрос к текущей: Мочи прочтёт его между шагами, ответ по ходу дела и итог придут в Telegram;
* `/status`, `/stop`, `/now` (прочитать новые сообщения сейчас, не дожидаясь конца шага), `/new` (очистить чат), `/web`, `/notify away|always|off`;
* когда задача из веба закончилась, а чат в браузере закрыт, Мочи пришлёт итог (режим `away`, по умолчанию).

Инструменты агента: `telegram_connect`, `telegram_status` (в т. ч. новая ссылка), `telegram_send`, `telegram_notify_mode`, `telegram_disconnect`. Бот отвечает только привязанному чату; остальным — «Это личный бот».

## Инструменты, MCP и навыки

Принцип: в памяти модели только то, что нужно сейчас, — но Мочи может сама подключить недостающее.

**Настройки → Инструменты** (применяется сразу). Всё разложено по папкам — «Встроенные» (по группам: Сервер, Файлы, Интернет, Telegram, Расширения), «MCP-серверы», «Навыки»; при открытии видны только заголовки с итогом справа («4 из 9 · ≈1018 ток.»). Вкладка «Сервер» так же разбита на «Аккаунт» и «Telegram».

* **Встроенные инструменты** — включает и выключает **только пользователь**: у агента нет для этого инструмента, а в подсказке он видит, что выключенное трогать не может. Каждый можно выключить (`run_command`, `read_file`/`view_image`/`edit_file`/`write_file`, `send_file`, поиск, Telegram, управление расширениями). Выключенный инструмент не уходит в запросы к модели, его абзац исчезает из системной подсказки, а вызвать его модель не сможет, даже если «вспомнит». Рядом с каждым — примерный «вес» в токенах, сверху — сколько занимают все включённые.
* **MCP-серверы** — HTTP (адрес + заголовки, например `Authorization: Bearer …`) или локальные stdio (команда, например `npx -y @modelcontextprotocol/server-memory`, + переменные окружения). Можно выключить сервер целиком или отдельные его инструменты. Режим **«по запросу»** (по умолчанию): в подсказке одна строка с именем сервера, а его инструменты появляются, только когда модель вызовет `mcp_connect` (до очистки чата).
* **Навыки (skills)** — папки с `SKILL.md` в формате Anthropic Agent Skills. В памяти модели **только имена** включённых навыков; описания модель получает вызовом `skill` без имени, полный текст — `skill(имя)`, остальные файлы навыка (скрипты, справка) — через `run_command`, когда понадобятся. Установка по ссылке: папка или репозиторий GitHub (`https://github.com/anthropics/skills/tree/main/skills/pdf`), прямой URL на `SKILL.md`; или свой навык прямо в форме. Навыки лежат в `~/ИМЯ/skills/`.

Агент делает то же сам: «подключи MCP-сервер …», «установи навык …», «сделай навык из того, что мы сейчас делали» — инструменты `mcp_manage` и `skills_manage`. Ключи из таких сообщений сохраняются в защищённых данных сервера и вычищаются из истории чата. Не хочешь, чтобы агент менял набор расширений, — выключи эти два инструмента.

## Безопасность

У агента есть настоящий shell на сервере, поэтому защита построена в несколько слоёв:

* **Регистрация только по одноразовому приглашению** (первое печатает установщик). Каждый пользователь Мочи фактически получает терминал сервера — приглашай только тех, кому доверяешь.
* **Пароли** — scrypt с солью, сравнение за постоянное время; ограничение 10 ошибок за 15 минут на IP и на имя.
* **Сессии** — 32 случайных байта в cookie `__Host-…; HttpOnly; Secure; SameSite=Strict`, на сервере хранится только хеш. Изменяющие запросы требуют заголовок `X-Mochi` и совпадения `Origin` (защита от CSRF).
* **Разделение привилегий.** Сервер (`mochi`) хранит пароли, сессии, ключи API и токены ботов в `/var/lib/mochi/data` (`0700`). Команды агента и терминал выполняются от **другого** пользователя — `mochi-agent`, — которому эти данные недоступны (права + `InaccessiblePaths` в systemd). Утёкший через prompt injection shell не достанет ключи.
* **ttyd** не слушает сеть вообще — только unix-сокет, доступный группе `mochi`, и принимает лишь запросы с заголовком, который ставит сервер **после проверки входа** (`--auth-header`). WebSocket — только с того же Origin (`-O` и проверка на сервере). Аргументы из URL не принимаются.
* **MCP и навыки.** Локальные MCP-серверы запускает исполнитель от имени `mochi-agent` — с теми же правами, что и команды агента (и агент может прочитать их переменные окружения). Настройки MCP с ключами хранятся в данных сервера и в браузер не отдаются (видны только имена заголовков и переменных). Папки навыков сервер читает с проверкой пути, а пишет в них только через исполнитель.
* **Проводник** (вкладка «Файлы») работает через тот же исполнитель от имени `mochi-agent` (подробнее — в «[Файлы (проводник)](#файлы-проводник)»): данных сервера он не видит, а содержимое файлов отдаёт с CSP `sandbox` и `nosniff` — HTML или SVG с сервера не исполнит скрипты на странице Мочи.
* **Файлы.** `read_file`, `view_image`, `edit_file` и `write_file` выполняет исполнитель от имени `mochi-agent` — прав у них ровно столько же, сколько у команд агента. `send_file` отдаёт только обычные файлы из рабочей папки; путь проверяется по открытому дескриптору, поэтому симлинк на данные сервера не пройдёт. Загрузки пишутся только в новые файлы (`O_EXCL|O_NOFOLLOW`). Скачивание — `attachment` с `nosniff` и `sandbox`-CSP, только своему владельцу.
* **Страница** — строгий CSP: скрипты только свои и встроенные по SHA-256 (без `unsafe-inline`), `frame-ancestors 'none'`; HSTS.
* **Службы systemd** — `NoNewPrivileges`, `ProtectSystem`, `ProtectHome`, `PrivateTmp`, пустой набор capabilities у сервера; Caddy получает только `CAP_NET_BIND_SERVICE`, его admin-API выключен.
* **Загрузки** Node.js, ttyd и Caddy проверяются по контрольным суммам; версии ttyd и Caddy закреплены, суммы зашиты в установщик.
* **Обновление из браузера** — только для администратора. Сервер лишь кладёт файл-запрос; что и откуда ставить, root-служба `mochi-update` решает сама по `/etc/mochi/install.conf` (из запроса не читается ничего). Агент (`mochi-agent`) положить запрос не может: данные сервера ему недоступны.
* Сервер Мочи **без npm-зависимостей** — нечему прилететь через цепочку поставок.

**Полный доступ агента (root)** снимает эту изоляцию целиком: агент сможет прочитать что угодно, включая данные сервера (см. «[Полный доступ агента](#полный-доступ-агента-root)»). Включить его может только администратор и только с паролем. Сам сервер Мочи root дать не может: он лишь просит root-службу, а та берёт из запроса одно слово — `on` или `off`.

## Разработка

```bash
cd server
npm run dev     # http://127.0.0.1:8787, данные в server/.dev, команды выполняются без отдельного пользователя
npm test        # тесты: вход, CSRF, агент, фоновая работа, остановка, файлы, файловые инструменты, проводник, перезапуск, Telegram, инструменты, MCP, навыки, обновления, доступ агента (root), быстрый старт (страница без образа Linux, поиск не держит агента)
```

Для первой регистрации в dev: `MOCHI_DEV=1 MOCHI_DATA=./.dev/data node mochi.js invite`.

Структура:

* `index.html`, `sw.js`, `manifest.webmanifest`, `icons/` — приложение: оформление, питомец, чат, проводник (сервер добавляет `server/public/client.js` — вход, поток событий, настройки сервера, терминал). Экран загрузки — первым делом в `<body>` (`#boot`, `window.mochiBoot`): его шаги двигает `client.js`;
* `server/mochi.js` — точка входа (`serve`, `runner`, `fileop` — файловая операция от root, `fsop`/`fsget`/`fsput` — то же для проводника, команды администратора);
* `server/lib/` — `server.js` (HTTP, SSE, CSP), `auth.js`, `agent.js` (фоновый агент), `runner.js` (исполнитель команд), `telegram.js`, `term.js` (прокси ttyd), `files.js`, `fsx.js` (проводник: список, поиск, копирование, архивы, чтение и загрузка), `rawio.js` (потоки «заголовок + байты» исполнителя), `mcp.js` (MCP-клиент: HTTP и stdio, поиск в интернете), `ext.js` (MCP-серверы и навыки пользователя), `update.js` (проверка обновлений и запрос на обновление), `access.js` (доступ агента: root вкл/выкл);
* `server/bin/mochi-update` — обновление от root (по кнопке в настройках и `sudo mochi update`);
* `server/bin/mochi-access` — полный доступ агента от root (по кнопке в настройках, `sudo mochi root on|off` и `install.sh --root`);
* `install.sh` — установщик.
