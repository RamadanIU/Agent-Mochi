# Personal Computer · облачный агент

Ламповый пиксельный компьютер-помощник, который живёт на твоём сервере и работает в настоящем Linux:

* **агент работает в фоне** — закрыл браузер, а задача идёт; вернулся — видно прогресс или итог;
* **[Personal Computer](#personal-computer-в-шапке)** в левом углу верхней панели — на его экране видно, что он делает прямо сейчас (настоящая команда, поисковый запрос, текст ответа), в облачке — объяснение модели к каждому шагу, а все шаги — в журнале;
* **[история чатов](#история-чатов)** — кнопка с часами в шапке: все разговоры по дням, поиск, названия придумывает сама модель;
* **терминал** сервера прямо в браузере (ttyd + tmux);
* **проводник** по файлам сервера (с правами агента, при полном доступе — и root);
* **вход** по приглашению, **Telegram** — управление и уведомления;
* **[прокси](#прокси-vless-vmess-trojan-shadowsocks-hysteria-2)** — вставил ключ `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` (или подписку) — и модель, поиск, Telegram и команды агента ходят в интернет через него.

> Браузерной версии (Linux в эмуляторе v86 на GitHub Pages) больше нет — Personal Computer работает только на сервере.

## Установка на сервер — одна команда

```bash
curl -fsSL https://raw.githubusercontent.com/RamadanIU/Agent-Mochi/HEAD/install.sh | sudo bash
```

Установщик сам:

1. определяет ОС, архитектуру и систему инициализации (Ubuntu/Debian, Fedora/RHEL/Rocky/Alma, Alpine, Arch, openSUSE; x86_64, arm64, armv7; systemd или OpenRC);
2. ставит пакеты, **Node.js 22**, **ttyd 1.7.7**, **Caddy 2.10** и **Xray 26.9.9** (для [прокси](#прокси-vless-vmess-trojan-shadowsocks-hysteria-2)) — с проверкой контрольных сумм;
3. заводит отдельных системных пользователей и службы;
4. получает HTTPS-сертификат Let's Encrypt — для своего домена или для адреса вида `1-2-3-4.sslip.io` (если домена нет);
5. печатает ссылку для первой регистрации:

```
  Открой и зарегистрируйся (первый пользователь станет администратором):
    https://203-0-113-7.sslip.io/?invite=k3x9-p2mf-q8wd
```

Дальше: **Настройки → Модель** — провайдер (OpenAI, Qwen и DeepSeek по токену аккаунта, [Kiro](#kiro-kirodev-по-аккаунту) — вход через Google в один клик, OpenRouter, Ollama Cloud, JustWoker, LM Studio или «Другой» — любой OpenAI-совместимый адрес, например свой Ollama `http://localhost:11434/v1`) и ключ. Ключ хранится на сервере и в браузер не возвращается.

Провайдеры сохраняются: у каждого свой ключ и последняя выбранная модель. Чтобы переключиться, выбери провайдера в списке (✓ — ключ уже сохранён) и нажми «Сохранить» — ключ заново вбивать не надо. Свои адреса («Другой») после сохранения тоже появляются в списке. «Забыть этого провайдера» под полем ключа стирает его ключ с сервера, «Сбросить всё» — ключи всех провайдеров.

Там же — **«Ограничение шагов»**: сколько шагов подряд (вызовов модели без твоих новых сообщений) Personal Computer делает в одной задаче, прежде чем остановиться, чтобы не зациклиться (по умолчанию 100 — меняется переменной `PERSONALCOMPUTER_MAX_STEPS` в `/etc/personalcomputer/personalcomputer.env`). Число можно поменять (от 1 до 10 000), а ограничение — выключить совсем: тогда Personal Computer работает, пока не закончит или пока не нажмёшь «Стоп».

### Параметры

```bash
curl -fsSL https://raw.githubusercontent.com/RamadanIU/Agent-Mochi/HEAD/install.sh | sudo bash -s -- --domain personalcomputer.example.com --email me@example.com
```

| Параметр | Что делает |
|---|---|
| `--domain NAME` | свой домен (A-запись → этот сервер) |
| `--email ADDR` | почта для Let's Encrypt |
| `--no-tls` | без HTTPS: Personal Computer слушает только `127.0.0.1:8787`, вход через SSH-туннель `ssh -L 8787:127.0.0.1:8787 сервер` |
| `--no-tls --public-url https://…` | свой обратный прокси (nginx и т. п.) перед `127.0.0.1:8787`, с поддержкой WebSocket |
| `--root` | полный доступ агента: root через `sudo` без пароля (то же — `--with-sudo`; потом переключается в настройках, см. «[Полный доступ агента](#полный-доступ-агента-root)») |
| `--no-root` | забрать у агента root (то же — `--no-sudo`). Без этих флагов повторная установка и `--update` оставляют доступ как был |
| `--update` | обновить код и зависимости, сохранив настройки и данные (то же — `sudo personalcomputer update` или кнопка в настройках) |
| `--uninstall [--purge]` | удалить (с `--purge` — вместе с данными) |

Нужны открытые порты **80 и 443** (у многих хостеров есть ещё облачный firewall в панели). Требования: 1 ГБ RAM, systemd или OpenRC.

### Управление

```bash
sudo personalcomputer invite        # ссылка-приглашение для нового пользователя
sudo personalcomputer users         # пользователи
sudo personalcomputer passwd ИМЯ    # сбросить пароль (новый будет напечатан)
personalcomputer status             # состояние служб
personalcomputer logs               # журнал
sudo personalcomputer restart
sudo personalcomputer update        # обновить (то же — кнопка в настройках)
sudo personalcomputer root on       # полный доступ агента (root); off — забрать, без слова — показать состояние
sudo personalcomputer browser       # браузер на сервере для окна проверки DeepSeek («я не робот», вход по паролю); status | remove
```

Коротко — `pc`: `sudo pc update`, `pc status` (если в системе нет своей команды `pc`).

### Обновление

Обновлять можно прямо из браузера. Personal Computer сам раз в 6 часов смотрит на GitHub, вышло ли что-то новое, и если да — администратору при входе выскакивает окошко с питомцем: «Ура! Вышло обновление!», список изменений и кнопки **«Позже»** / **«Обновить»**. «Позже» — напомнит через сутки (или когда выйдет следующая версия); на шестерёнке настроек горит точка.

То же вручную: **Настройки → Сервер → Обновления** — какая версия стоит, «Проверить обновления», «Обновить».

После «Обновить» Personal Computer показывает ход работы (шаги установщика и полоску), сервер перезапускается примерно на минуту, страница сама перезагружается уже с новой версией. Переписка, настройки и файлы сохраняются, начатые задачи агента продолжаются сами. Если что-то пошло не так — видно, на каком шаге, и можно нажать «Повторить» (установщик безопасно запускать повторно). Остальные открытые вкладки и устройства перезагрузятся сами, когда увидят новую версию сервера.

Как это устроено:

* **Что стоит.** Установщик кладёт рядом с кодом `build.json`: репозиторий, ветку и точный коммит (GitHub пишет его в заголовок архива с кодом).
* **Что нового.** Сервер сравнивает этот коммит с последними коммитами той же ветки через API GitHub (с ETag: повторная проверка не тратит лимит) или, если лимит API в 60 запросов в час исчерпан (бывает на общем IP хостинга), — через ленту `github.com/…/commits.atom`. В окошке — названия изменений (у слияний PR — название PR).
* **Обновить.** Сам сервер обновиться не может: он работает без прав root. Поэтому кнопка только кладёт файл-запрос в данные сервера, а его замечает отдельная root-служба (`personalcomputer-update.path` в systemd, `personalcomputer-updater` в OpenRC) и запускает `server/bin/personalcomputer-update`. Тот берёт **свои** настройки (`/etc/personalcomputer/install.conf`: репозиторий и ветку), узнаёт точный последний коммит, скачивает `install.sh` и код ровно этого коммита и запускает `install.sh --update`. Из запроса не берётся ничего — даже взломав сервер Personal Computer, нельзя подсунуть другой код или старую версию.
* **Ход работы** — в `/var/lib/personalcomputer/update`: `status.json` и `steps.log` (только строки шагов) читает сервер, полный журнал `install.log` — только root.

> **Если Personal Computer стоит давно** (до появления этой кнопки): один раз обновись вручную — `sudo personalcomputer update`. Эта команда поставит службу обновления, дальше хватит кнопки.

> **Переезд со старого имени.** До переименования всё на сервере называлось `mochi`: пользователи `mochi` и `mochi-agent`, папки `/opt/mochi`, `/var/lib/mochi`, `/etc/mochi`, службы `mochi*`, команда `mochi`. Первое обновление (кнопкой или `sudo mochi update`) переносит всё это на `personalcomputer`: пользователей и группы переименовывает (UID и GID прежние), папки переносит как есть, ставит службы под новыми именами, а старые убирает. Переписка, ключи, сертификат, рабочие папки и расписания cron агента сохраняются, входить заново не нужно. Ссылки `/opt/mochi` и `/var/lib/mochi` живут, пока доработает прежняя служба обновления, потом исчезают — если в своих скриптах или виртуальных окружениях Python агент прописывал пути `/var/lib/mochi/…`, их надо поправить на `/var/lib/personalcomputer/…` (venv проще создать заново).

### Полный доступ агента (root)

По умолчанию агент работает как обычный пользователь `personalcomputer-agent`: свои папки, пакеты Python и npm — к себе, без `sudo`. Если Personal Computer должен администрировать сервер — ставить системные пакеты, настраивать nginx, Docker и службы, править `/etc`, — дай ей полный доступ:

* **Настройки → Сервер → «Доступ агента» → «Дать полный root»** — только администратор и только с подтверждением паролем. Забрать — там же, одной кнопкой;
* или на сервере: `sudo personalcomputer root on` / `sudo personalcomputer root off` / `sudo personalcomputer root` (что сейчас);
* или сразу при установке: `… | sudo bash -s -- --root`.

Что меняется:

* `personalcomputer-agent` получает `sudo` без пароля — правило `/etc/sudoers.d/personalcomputer-agent`, проверенное `visudo`. Под sudo umask `0022`, поэтому файлы в `/etc` и `/var/www` читаются службами. В `PATH` есть Node.js Personal Computer, а `DEBIAN_FRONTEND` и похожие переменные сохраняются, так что `apt` и `pip` не задают вопросов. Если sudo не понимает этих настроек (например, `sudo-rs`), пишется только само правило.
* С исполнителя команд и терминала снимается изоляция systemd — drop-in `personalcomputer-runner.service.d/personalcomputer-root.conf` и такой же для `personalcomputer-term`. С `NoNewPrivileges`, `ProtectSystem` и прочими ограничениями sudo не работает. Сами службы в установщике по-прежнему изолированы: убери drop-in — и изоляция вернётся.
* **Файловые инструменты** (`read_file`, `view_image`, `edit_file`, `write_file`) сначала работают от `personalcomputer-agent`. Если прав не хватило, они повторяют то же от root (`sudo node personalcomputer.js fileop`). Агент правит `/etc/nginx/nginx.conf` так же, как свои файлы; владелец и права чужих файлов сохраняются, а в ответе отмечено «сделано от root».
* Агент знает о root из системной подсказки. Системное он делает через `sudo`, перед необратимым (удаление данных, переустановка, настройки SSH и firewall) спрашивает, а службы Personal Computer без просьбы не трогает. Без root он подскажет, где его включить.
* **Терминал**: в строке состояния — `[pc·root]`, root-оболочка — `sudo -i`.
* Доступ переживает обновления и повторную установку (`/etc/personalcomputer/install.conf`).

Как это устроено. У сервера Personal Computer нет прав, поэтому он только кладёт файл-запрос. Из запроса берётся одно слово, `on` или `off`, больше ничего. Запрос забирает root-служба: `personalcomputer-access.path` в systemd или `personalcomputer-updater` в OpenRC. Она запускает `server/bin/personalcomputer-access`, и тот:

1. пишет правило и drop-in;
2. перезапускает исполнитель и терминал — идущие команды обрываются, агент это видит и продолжает;
3. проверяет, что sudo действительно работает;
4. пишет итог в `/var/lib/personalcomputer/update/access.json`, который показывают настройки.

Если ничего не поменялось, службы не перезапускаются. При выключении служба проверяет, не осталось ли у `personalcomputer-agent` прав root из чужих правил sudo или групп (`sudo`, `wheel`, `docker`…), и предупреждает о них. Переключение и обновление не идут одновременно: у них общий замок. Если агент (или кто-то в терминале Personal Computer) сам выполнит `sudo personalcomputer update`, `sudo personalcomputer restart` или `sudo personalcomputer root off`, команда не оборвёт себя на полпути — она уйдёт через root-службу.

> **Осторожно.** Root получает **каждый** пользователь Personal Computer: агент и терминал у всех общие. А prompt injection — инструкция, спрятанная на сайте или в файле, который прочтёт агент, — сможет управлять всем сервером, в том числе прочитать ключи API и пароли Personal Computer. Включай root, только если доверяешь всем пользователям и сервер не жалко. Выключение забирает sudo, но всё, что агент успел поменять в системе, остаётся.

## Как это работает

```
 браузер / телефон ──HTTPS──▶ Caddy :443 ──▶ сервер Personal Computer 127.0.0.1:8787 (пользователь personalcomputer)
                                               │  ├─ вход, сессии, чат, SSE-поток событий
                                               │  ├─ агент (цикл модели) и Telegram-бот
                                               │  ├─ прокси /term/ (только после входа)
                                               │  └─ Xray 127.0.0.1 (если включён прокси) ──▶ твой сервер VLESS/VMess/… ──▶ интернет
                                               │
                 unix-сокеты (группа personalcomputer) ───┼──▶ personalcomputer-runner  — выполняет команды агента
                                               └──▶ ttyd + tmux   — терминал     (пользователь personalcomputer-agent)
```

* **Фоновая работа.** Задача живёт на сервере. Чат в браузере только подписывается на поток событий (`/api/stream`): закрыл вкладку — работа идёт; открыл — в шапке видно, чем Personal Computer занят, а все шаги и итог — в его журнале. Состояние на диске, поэтому даже перезапуск сервера не теряет задачу: она продолжится сама.
* **Сообщения во время работы.** Пока Personal Computer работает, писать можно как обычно (Enter или кнопка «Отправить»; рядом появляется отдельная кнопка «Стоп»). Сообщение не отклоняется, а ждёт над полем ввода и уходит модели в ближайшей паузе между шагами — после текущей команды или ответа модели — с пометкой «во время работы»: модель понимает, что это дополнение, новая просьба или вопрос по ходу дела, учитывает его и продолжает задачу, а на вопрос отвечает сразу. Пришло, пока модель дописывала итоговый ответ, — она ответит и на него в той же задаче.
  * **«Прочитать сейчас»** — не ждать конца шага: долгая команда или ответ модели прерываются, и модель читает сообщения немедленно (задача продолжается).
  * **«X»** у сообщения — отозвать, пока модель его не прочла: текст (и вложения) вернутся в поле ввода.
  * Лимит шагов считается от последнего твоего сообщения: дописал по ходу — счётчик начинается заново.
* **«Стоп» — мгновенно.** Агент больше не ждёт, пока прерванная операция закончится: команда, которая не реагирует на SIGTERM (apt, сборки, `sudo`), раньше держала «Стоп» до SIGKILL (3 с), а подключение к MCP-серверу или поиску — до 10–30 с. Теперь задача останавливается сразу (десятки миллисекунд), а исполнитель добивает процесс в фоне. Кнопка откликается без ожидания потока событий: сервер отвечает на «Стоп», когда задача уже остановлена. Сообщения, которые модель не успела прочесть, остаются в переписке, а под отметкой «Остановлено» — кнопка «Продолжить»: Personal Computer ответит на них.
* **Экран загрузки.** Пока Personal Computer просыпается, его окошко показывает «BIOS» с шагами — страница, сервер (пинг), вход, модель, чат (сколько сообщений), агент (свободен или работает), — сколько занял каждый шаг и сколько осталось ждать. Прогноз — по прошлым загрузкам на этом устройстве (медиана пяти последних по каждому шагу), в первый раз — по скорости сети, которую знает браузер. Шаг затянулся — объясняет почему; сервер не отвечает (перезапуск, обновление, пропала сеть) — говорит об этом, сама повторяет попытки с обратным отсчётом и продолжает, как только сервер вернётся. Если в этот момент Caddy отвечает 502, страница берётся из кэша, а когда сервер проснётся — обновляется сама. Итог каждой загрузки — в консоли браузера («Personal Computer: загрузка 1,2 с …»).
  * Страница лёгкая — ~160 КБ в сжатом виде (раньше в ней был целый Linux для браузерной версии, 3,8 МБ): на сети 4 Мбит/с Personal Computer готов меньше чем за секунду, а не через 9.
  * Длинная история: сначала рисуются последние 100 сообщений, раньше — по кнопке «Показать раньше» или когда долистаешь до неё; позиция при этом не прыгает. 400 записей с таблицами и кодом на слабом телефоне рисовались ~4 с, теперь ~1 с.
  * MCP-серверы (и поиск в интернете) сервер подключает сразу при старте, а сервер, чьих инструментов ещё не знает, агент ждёт не дольше 2,5 с — подключение идёт в фоне, и инструменты появляются со следующего шага: раньше первое сообщение после перезапуска ждало подключения к поиску, а если поиск не отвечал — до 10 с.
* **Терминал.** Вкладка «Терминал» — настоящий shell сервера в tmux: можно закрыть браузер, а запущенное продолжит работать. Команды агента видны прямо в нём: Personal Computer «печатает» команду (с меткой `PC`) и выводит её результат, а потом возвращает твоё приглашение вместе с недонабранной строкой. Если в терминале открыта твоя программа (vim, top…), агент её не перебивает. Кнопки Esc/Ctrl+C/Tab/стрелки и строка ввода удобны на телефоне.
* **Файлы.** Прикреплённое в чате попадает в `~/ИМЯ/inbox/`, результаты агент отдаёт через `send_file` — в чате появляется кнопка «Скачать». Всё остальное — во вкладке «[Файлы](#файлы-проводник)».
* **Работа с кодом и текстом.** Файлы агент читает и правит своими инструментами, а не через `cat`/`sed`/heredoc: так нет проблем с экранированием, тихих «ничего не заменилось» и случайно стёртых файлов. Поиск, запуск, сборка и git — по-прежнему через `run_command`.
  * `read_file` — строки с номерами, срезы (`offset`/`limit`, отрицательный `offset` — хвост лога) и подсказка, откуда продолжить; вывод ограничен (~40 тыс. символов), длинные строки обрезаются, двоичное не выводится. Тот же кусок той же версии файла повторно не выводится — модель получает короткую отсылку к уже прочитанному.
  * `view_image` — агент сам смотрит на картинку с сервера (фото, скриншот, график): PNG, JPEG, GIF или WebP до 8 МБ, формат определяется по байтам, а не по расширению. Результат инструмента у OpenAI-совместимых API бывает только текстом, поэтому картинка уходит модели следующим сообщением — как вложение пользователя. Нужна модель со зрением; если модель картинки не принимает или зрение выключено в настройках, инструмент так и отвечает. Другие форматы (SVG, PDF, HEIC) агент сначала конвертирует в PNG командой. `read_file` на картинке подсказывает `view_image`.
  * `edit_file` — замена точного фрагмента `old_string` → `new_string`, который обязан встречаться один раз (или `replace_all`). Несколько правок файла — одним вызовом (`edits`): по порядку, все или ни одной. Если фрагмент не найден, модель видит самое похожее место с номерами строк; если правка уже сделана — так и сказано. Прощаются частые ошибки: номера строк, скопированные из `read_file`, и расхождения только в пробелах по краям строк (отступы новой версии подгоняются под файл). В ответе — изменённые строки с соседними, перечитывать файл не нужно.
  * `write_file` — создать файл (с папками) или заменить целиком. Непустой существующий файл перезаписывается, только если агент читал именно эту его версию (не изменённую потом командой).
  * Общее: запись атомарная (временный файл + `rename`), сохраняются права, окончания строк CRLF, BOM, симлинки и жёсткие ссылки; файлы не в UTF-8 не портятся. Заглушки вместо кода («`// ... остальное без изменений`») не дадут стереть настоящий код — пропускаются, только если модель повторит тот же вызов. После записи JSON, JS, Python и shell быстро проверяются на синтаксис, и модель получает предупреждение — но только если сломала именно эта правка.

## Файлы (проводник)

Третья вкладка — «Файлы»: файловая система сервера в виде окна старого компьютера. Полосатый заголовок с названием папки, строка «12 объектов · 1,4 МБ · свободно 10 ГБ», как в старом Finder, а внутри — папки и файлы **сеткой** из пиксельных значков 24×24 (или списком на «зелёнке», как распечатка старого принтера). Цвета значков — из выбранной темы: розовые папки у «Для девочек», голубые у «Для мальчиков», янтарные у «Ламповой»; в тёмной теме — те же, только приглушённые. В «Современной» значки векторные: синие папки и листы с цветной меткой типа файла.

* **Папки** открываются двойным щелчком (на телефоне — касанием): значок раскрывается, и из него в окно «вылетают» пунктирные рамки — та самая анимация из старых систем. «Наверх» — рамки сворачиваются обратно в папку, из которой пришёл, и она мигает. У особых папок свои значки: дом, входящие и исходящие, навыки (сердечко), код, фото, музыка, видео, `/etc`; корень `/` — жёсткий диск.
* **Значки по типу файла**: картинка, видео, музыка, код, текст, Markdown, таблица, PDF, архив (с молнией), шрифт, программа (экранчик `>_`), настройки (шестерёнка), ключи, образы дисков, двоичное (`0101`). Ссылки — со стрелкой и курсивом, битые — с красным крестиком; скрытые — бледные. У картинок — миниатюры в рамке (пиксель-арт увеличивается без размытия).
* **Навигация**: назад/вперёд/наверх, «крошки» пути (щелчок по пустому месту — ввести путь, `~` — домашняя папка), «Места» (своя папка, inbox/outbox, навыки, папка агента, корень, `/tmp`, `/etc`, `/var/log`), поиск — набор сразу отбирает в текущей папке, Enter ищет по всем вложенным (`*.jpg`, `report?.txt`). Сортировка по имени, размеру, дате, типу; три размера значков; скрытые файлы — по желанию. Последняя открытая папка запоминается. Пока вкладка открыта, папка обновляется сама: если Personal Computer создал файл, он тут же появится.
* **Выделение**: щелчок, Ctrl/Shift, рамка «бегущие муравьи» по пустому месту; на телефоне — долгое касание, дальше касаниями. Снизу — панель действий.
* **Действия**: открыть, скачать (папку — архивом `.tar.gz`), копировать/вырезать/вставить, дублировать, переименовать прямо в подписи (F2), новая папка/файл, удалить (с подтверждением — корзины нет), сжать в `.tar.gz`, распаковать ZIP и tar-архивы, «Свойства» (размер, в том числе папки целиком, даты, владелец, права с галочками `rwx`), копировать путь, «Открыть в терминале» (вкладка «Терминал» сразу переходит в папку), **«Спросить»** (Personal Computer) — путь вставляется в чат, осталось написать, что сделать.
* **Загрузка**: перетащи файлы или целые папки в окно (или на значок папки), либо «Загрузить файлы/папку» в меню. Окошко «Копирование» с полосой и скоростью, отмена; одинаковые имена — «Заменить» или «Оставить оба». Значки можно перетаскивать в папки, «крошки» и «Места» (с Ctrl/Alt — копировать).
* **Клавиатура**: стрелки, Home/End, Enter — открыть, Backspace / Alt+↑ — наверх, Alt+←/→ — назад/вперёд, Пробел — быстрый просмотр, F2, Delete, Ctrl+A/C/X/V/D, Ctrl+I — свойства, Ctrl+Shift+N — новая папка, Ctrl+F — поиск, F5, первые буквы имени — перейти к файлу, Shift+F10 — меню.

**Просмотр** — окно поверх папки, тоже с полосатым заголовком; ←/→ (или Alt+←/→) листают соседние файлы того же вида:

| Что | Как открывается |
|---|---|
| Картинки (PNG, JPEG, GIF, WebP, AVIF, BMP, ICO, SVG…) | на «шахматке», вписать / 1:1 / колесо и щипок — зум, перетаскивание, свайп — соседние; маленькие увеличиваются чётко по пикселям |
| Видео (MP4, WebM, MOV, MKV, OGV) | свой пиксельный пульт: перемотка (с подгрузкой кусками — `Range`), громкость лесенкой, скорость, по кругу, весь экран и режим «ЭЛТ» — строки развёртки старого телевизора; клавиши Пробел/K, ←/→, J/L, M, F, 0–9 |
| Музыка (MP3, OGG, Opus, WAV, FLAC, M4A, AAC) | кассетный плеер: катушки крутятся, название — на наклейке, спектр из «лампочек» как на музыкальном центре, список песен из папки, следующая включается сама |
| Текст и код | экранчик с номерами строк и подсветкой (JS/TS, Python, shell, C/C++, Go, Rust, Java, PHP, SQL, YAML, JSON, HTML, CSS, Dockerfile, ini/conf…), логи — ошибки красным, предупреждения жёлтым; перенос строк, «красивый» JSON, кодировки UTF-8/UTF-16/CP1251. **Правка** прямо здесь: Ctrl+S — сохранить, Tab — отступ; концы строк CRLF и BOM сохраняются, а если файл тем временем поменяли (например, Personal Computer), будет вопрос, а не тихая перезапись |
| Markdown, CSV, HTML | «Просмотр»: Markdown — тем же оформлением, что ответы Personal Computer (относительные картинки и ссылки на другие файлы работают), CSV — таблицей, HTML — страницей в песочнице без скриптов |
| PDF | встроенным просмотрщиком браузера (где его нет — открыть в новой вкладке или скачать) |
| Шрифты (TTF, OTF, WOFF, WOFF2) | алфавиты и «Съешь же ещё этих мягких французских булок» разными размерами |
| Архивы (ZIP, tar, tar.gz/xz/bz2) | что внутри (пути, размеры, даты) и «Распаковать сюда» |
| Всё остальное | HEX — как в старом дисковом редакторе, «как текст», скачать |

Как это устроено:

* **Права.** Проводник работает через исполнитель команд — от имени `personalcomputer-agent`, ровно с теми же правами, что агент и терминал; данные сервера Personal Computer (`/var/lib/personalcomputer/data`) ему недоступны. При [полном доступе](#полный-доступ-агента-root) то, на что прав не хватило (`/root`, `/etc/shadow`…), повторяется от root (`sudo node personalcomputer.js fsop|fsget|fsput`), а в заголовке окна загорается `ROOT`. Корень, папки верхнего уровня (`/etc`, `/usr`…) и домашнюю папку агента нельзя удалить или унести — даже от root.
* **Байты** идут отдельным соединением с исполнителем: строка-заголовок JSON, дальше сырые данные — без base64 и без чтения файла в память. Отдача — с `Range` (перемотка видео) и `ETag`; загрузка — потоком во временный файл рядом, потом под своё имя (`link()` — без перезаписи), оборванная загрузка удаляется.
* **Безопасность страницы.** Файлы с сервера никогда не исполняются: ответы `/api/fs/raw` — с `nosniff` и CSP `sandbox` без скриптов, HTML и прочее неизвестное — как `text/plain` или скачиванием, SVG — только картинкой. Предпросмотр HTML — в `<iframe sandbox>` без скриптов. Изменяющие запросы — с той же защитой от CSRF, что и всё API.
* **Архивы**: ZIP разбирается самим сервером (центральный каталог, deflate через zlib) — `unzip` не нужен; tar — системным `tar`. Пути с `..` пропускаются, ведущий `/` отрезается, символические ссылки из ZIP не создаются.
* **Размер загрузки** — до 4 ГБ на файл (`PERSONALCOMPUTER_MAX_UPLOAD_MB` в `/etc/personalcomputer/personalcomputer.env`).
* **API**: `GET /api/fs/info|list|stat|search|du|archive`, `GET|HEAD /api/fs/raw` (`dl=1` — скачать), `GET /api/fs/tar` (папка архивом), `PUT /api/fs/upload?dir=&name=[&over=1]`, `POST /api/fs/op` (`mkdir`, `newfile`, `rename`, `copy`, `move`, `delete`, `chmod`, `write`, `extract`, `pack`).

### Подключение к API модели

* **Запросы к модели** (`/chat/completions`, `/models`) делает сам сервер из Node.js — CORS к ним не применяется, подходит любой OpenAI-совместимый адрес. Свой Ollama или LM Studio на том же сервере — «Другой» и `http://localhost:11434/v1` (Ollama) или `http://localhost:1234/v1` (LM Studio).
* **Проверка в настройках.** Кроме `/models`, сервер шлёт пустой запрос к `/chat/completions` (без модели и сообщений — ничего не запускается, токены не тратятся): так видно, подходит ли ключ там, где `/models` открыт всем, и не закрыл ли Cloudflare запросы к модели.
* **Ollama Cloud** (`https://ollama.com/v1`) — ключ — на [ollama.com/settings/keys](https://ollama.com/settings/keys). Список моделей открыт и без ключа, поэтому без ключа Personal Computer пишет «Вставь API ключ».
* **JustWoker** (`https://api.justwoker.icu/v1`) — шлюз New API, ключ вида `sk-…` из его панели. Перед ним Cloudflare, который может блокировать запросы к модели с некоторых IP (например, сетей хостинга), хотя список моделей отдаёт. Тогда Personal Computer так и пишет — «Это не ключ: Cloudflare … заблокировал запрос» с Ray ID для поддержки; помочь может только владелец шлюза или другой сервер.
* **Cloudflare.** Если API отвечает страницей блокировки Cloudflare, Personal Computer один раз повторяет запрос через `curl` (так проходит OpenRouter) и, если не помогло, показывает понятную ошибку вместо «ключ не подошёл».

### Qwen (chat.qwen.ai) по токену аккаунта

Отдельный провайдер **«Qwen (chat.qwen.ai)»**: модели Qwen бесплатно, через твой обычный аккаунт на [chat.qwen.ai](https://chat.qwen.ai). Сервер Personal Computer сам говорит с веб-API сайта — **без сторонних прокси и шлюзов** (если в настройках → Сервер включён прокси, запросы идут через него).

1. Настройки → Модель → Провайдер «Qwen (chat.qwen.ai)».
2. Подключи аккаунт. В карточке «Аккаунт Qwen» — три способа, каждый отдельно (объяснения спрятаны под «?»: на компьютере — облачко, на телефоне — окошко; на телефоне его открывает и долгое нажатие на строку настройки):
   * **Вход по email и паролю** (лучший) — папка «Вход по email и паролю». Сервер сам входит на chat.qwen.ai, получает токен и дальше **обновляет его сам, до истечения** — вставлять токен не нужно никогда. Сам пароль не хранится: только его хеш SHA-256 (именно его chat.qwen.ai и принимает при входе) — на сервере, рядом с ключами API.
   * **«Войти через Google»** — для входа через Google или GitHub, где пароля нет (с компьютера). Кнопка сама открывает окно chat.qwen.ai, ты входишь там через Google и нажимаешь закладку «Токен Qwen» — токен возвращается в Personal Computer сам (сообщением окну приложения, только на его адрес; приложение отвечает «принято», и окно сайта закрывается) и сохраняется без лишних вопросов: окно открыло само приложение, а отправитель проверен по адресу сайта. Закладку один раз перетаскивают на панель закладок прямо из подсказки под кнопкой; без закладки — «Скопировать команду» и вставить её в консоль окна сайта (F12 → Console). Окно сайта открыто не из приложения — токен, как раньше, приходит после `#` в адресе, и Personal Computer спрашивает подтверждение. С телефона закладок и консоли нет — подключи с компьютера или войди «в окне приложения».
   * **«Войти в окне приложения»** — настоящая страница входа chat.qwen.ai в браузере на сервере (окно с живым экраном, как у проверки «я не робот»): вход по email, GitHub и т. п. — токен забирается из вкладки сам. **Вход через Google в этом окне не работает и обходить это мы не будем:** Google нарочно не пускает в аккаунт браузер, которым управляет программа («This browser or app may not be secure»). Поэтому для Google-аккаунтов — кнопка «Войти через Google» выше: вход идёт в твоём собственном браузере. Всплывающие окна, которые сайт открывает в браузере на сервере, сразу закрываются (их не видно и на них не действует список разрешённых адресов) — окно объясняет, что делать.
   * **«Токен вручную»** — папка с полем токена; команда для консоли (`copy(localStorage.token)`) — в справке под «?» с кнопкой «Копировать». Подойдёт и с `Bearer`, и строкой cookie.
3. Карточка покажет статус: «Подключён», чей аккаунт и до какого времени действует токен (или «токен обновляется сам»), — либо коротко, что не так (подробности — под «?»). Подключённому способы входа не мешают: они спрятаны под «Другой аккаунт», рядом — «Отключить». Список моделей подгрузится сам (только модели обычного чата) — выбери модель и сохрани.

**Обновление токена.** Токен сайта живёт недолго (бывает — 15 минут), поэтому Personal Computer обновляет его сам: перед каждым запросом, если осталось меньше 2 минут, и фоном — за 5 минут до истечения (фоном — только пока ты пользуешься Qwen, последние 6 часов). Сначала он спрашивает у сайта текущую сессию (`/api/v1/auths/`) — если сайт выдал токен новее, берёт его; не вышло — входит заново по сохранённому паролю. Если Qwen всё-таки ответил «токен недействителен» (отозвали раньше срока), токен обновляется и запрос повторяется сам. Без пароля (вход через Google и т. п.) продление зависит от сайта; когда токен всё же истёк — в чате будет просьба подключить заново, и «Войти через Google» делает это за пару секунд.

Из настроек Qwen — только **модель** и **«Размышление»** (вкл/выкл; у моделей, которые всегда думают, переключатель заблокирован). Всё остальное у Qwen выключено принудительно: поиск в интернете, интерпретатор кода, картинки, видео, исследования — у Personal Computer свои инструменты (сервер, файлы, MCP), и модель не путает два рабочих пространства.

* **Инструменты агента.** Веб-API Qwen не знает вызовов функций, поэтому договорённость текстовая: модель пишет блок `[TOOL CALL] {"name": …, "arguments": {…}} [END TOOL CALL]`, результат получает блоком `[TOOL RESULT: имя] … [END TOOL RESULT]`. Родной тег Qwen `<tool_call>` не годится — его перехватывает сама платформа. Блоки разбираются на лету и в чате не видны; если модель после вызова начинает «додумывать» результат, этот текст отбрасывается.
* **История.** Каждый чат Personal Computer — один и тот же чат на chat.qwen.ai (его видно и на сайте). Под каждым ответом модели в истории лежит скрытая метка: id чата Qwen, id ответа, аккаунт и версия инструкции. Пользователь её не видит, другим провайдерам она не уходит. Следующий шаг продолжает тот же чат Qwen от этого ответа и отправляет **только новое** — сообщение пользователя или результаты инструментов, а не всю переписку; контекст хранит сам Qwen. Инструкция (характер, инструменты) уходит один раз и повторно — только если изменилась (включили инструмент, подключили MCP). «Повторить» и «Прочитать сейчас» продолжают от последнего сохранённого ответа — как ветка «перегенерировать» на сайте.
* **Если чата больше нет** (удалили на сайте, вставили токен другого аккаунта, переключились с другого провайдера) — заводится новый чат Qwen, и в него одним сообщением уходят инструкция и переписка (старые результаты команд — сокращённо).
* **Файлы в чат.** Прикреплённые к сообщению (в браузере или в Telegram) картинки и документы уходят в Qwen так же, как с сайта: временный ключ на загрузку → хранилище Alibaba OSS → Qwen разбирает документ → файл прикладывается к сообщению. Картинки (PNG, JPEG, GIF, WebP, BMP — до 5 за раз) модель видит сама, документы (PDF, Word, Excel, PowerPoint, TXT, MD, CSV — до 5) читает целиком; до 20 МБ на файл. Картинку с сервера агент тоже может показать модели — инструментом `view_image`. Остальное (архивы, видео, код) модели не отправляется: файл в любом случае лежит в `inbox/`, и агент открывает его своими инструментами. Не получилось загрузить — модель получает пометку, почему, и путь к файлу. Каждый файл уходит в чат Qwen один раз (повторно тот же файл не загружается); если чат пришлось начать заново, свежие файлы из переписки прикладываются снова.
* **Название чата** модель придумывает во временном чате Qwen, который сразу удаляется, — аккаунт не засоряется.
* **Ошибки — по-человечески:** «токен не подошёл или истёк», «исчерпан лимит запросов аккаунта», «chat.qwen.ai не пустил запрос с этого сервера» (защита Alibaba Cloud: обычно помогает прокси в настройках → Сервер).
* Версию фронтенда сайта (заголовок `Version`) можно задать `PERSONALCOMPUTER_QWEN_VERSION` в `/etc/personalcomputer/personalcomputer.env`, если chat.qwen.ai начнёт отвечать `Bad_Request` (на такой ответ сервер и сам один раз пробует узнать текущую версию со страницы сайта).

#### Qwen: антибот Alibaba Cloud — слайдер в окне приложения

У chat.qwen.ai своя защита (Alibaba Cloud): на подозрительные запросы она отвечает не ответом модели, а слайдером «я не робот» (HTTP 200, `ret` с `FAIL_SYS_USER_VALIDATE` / `RGV587_ERROR` и адрес слайдера `…/_____tmd_____/punish`). Раньше это была ошибка «chat.qwen.ai не пустил запрос», теперь — так же, как у DeepSeek:

* **Как из вкладки браузера.** Свой «браузер» у пользователя (`qwen.json`): User-Agent и `sec-ch-ua` как у Chrome, `sec-fetch-*`, cookies сайта (в том числе отметка о пройденном слайдере) — между перезапусками. Токены защиты сайта (`bx-ua`, `bx-umidtoken`) не подделываются: устаревшие, по наблюдениям, сами вызывают проверку.
* **Сообщение — не больше ~96 КБ.** На тело запроса больше ~128 КБ chat.qwen.ai отвечает слайдером (замерено: 117 КБ проходят, 129 КБ — нет). Поэтому размер считается в байтах (кириллица — два байта на букву): длинная переписка и длинные результаты инструментов (больше 30 000 символов — начало и конец) сокращаются, инструкция — никогда.
* **Без спешки:** ответы аккаунта по очереди, не чаще 15 в минуту; после слайдера 45 минут «бережный режим».
* **Слайдер — не ошибка, а пауза.** В чате карточка «Нужна проверка» → «Пройти проверку» → окно с той самой страницей слайдера, что назвал сайт, в браузере на сервере (тот же адрес, прокси, User-Agent и cookies). Тянешь слайдер мышью или пальцем (вбок — тянется, вверх-вниз — прокрутка) — cookies переходят в «браузер» сервера, задача продолжается сама. **Галочка в окне — только когда сам сервер убедился, что сайт пускает его запросы:** он спрашивает адрес ответа модели для несуществующего чата (модель не запускается, чат не создаётся) — защита пустила, значит, сайт ответит «чата нет», не пустила — снова слайдером. Сайт в браузере открылся, а запросы сервера всё ещё не пускает — окно так и говорит и не закрывается (раньше хватало открывшейся страницы, и окно закрывалось с галочкой зря). То же у DeepSeek: «не удалось спросить» или «токен не подошёл» — не повод для галочки. Не до того — она ждёт и пробует снова через 5, 15, 30 минут (днём по Пекину защита строже, ночью часто пускает сама). Вход по email и паролю, попавший на слайдер, — то же: «Пройти проверку» в карточке аккаунта, потом вход повторяется.
* Паузу и предел ответов в минуту можно задать `PERSONALCOMPUTER_QWEN_GAP_MS` и `PERSONALCOMPUTER_QWEN_RPM` (0 — без предела), размер сообщения в байтах — `PERSONALCOMPUTER_QWEN_MAX_BYTES`.

### DeepSeek (chat.deepseek.com) по аккаунту

Отдельный провайдер **«DeepSeek (chat.deepseek.com)»**: DeepSeek бесплатно, через твой обычный аккаунт на [chat.deepseek.com](https://chat.deepseek.com), — устроен так же, как Qwen: сервер Personal Computer сам говорит с веб-API сайта, **без сторонних прокси и шлюзов** (если в настройках → Сервер включён прокси, запросы идут через него).

1. Настройки → Модель → Провайдер «DeepSeek (chat.deepseek.com)».
2. Подключи аккаунт. В карточке «Аккаунт DeepSeek» — три способа (объяснения — под «?»):
   * **Вход по email (или телефону) и паролю** — сервер сам входит на chat.deepseek.com (`/api/v0/users/login`, тело как у сайта) и сохраняет токен, а когда тот истечёт — **входит заново сам**, посреди задачи и незаметно для тебя. Телефон — с кодом страны (`+7 900 …`; без кода — `+86`, как у сайта). Сайт принимает только сам пароль, поэтому он лежит на твоём сервере **зашифрованным** (AES-256-GCM, ключ — `data/secret.key`, 0600) и никуда, кроме chat.deepseek.com, не уходит; «Отключить» стирает его вместе с токеном и cookies сайта.
     Вход по паролю DeepSeek пускает только из браузера, который знает (отпечаток устройства SDK Shumei; без него или с выдуманным — `RISK_DEVICE_DETECTED`). Отпечаток Personal Computer берёт только настоящий: из браузера на сервере (если он есть — молча, за пару секунд), а если сайт и его не узнал — откроет **окно «Вход в DeepSeek»** с настоящей страницей входа (см. ниже): входишь там один раз, токен и вход по паролю сохраняются. Без браузера на сервере — один раз нажми «Войти через Google» с компьютера: закладка принесёт и отпечаток твоего браузера.
   * **«Войти через Google»** (с компьютера) — для входа на сайте через Google (и любого другого). Как у Qwen: кнопка открывает окно chat.deepseek.com, ты входишь через Google и нажимаешь закладку «Токен DeepSeek» — токен вместе с отпечатком устройства и User-Agent этого браузера (дальше сервер ходит на сайт «от его имени») возвращается в приложение сам, окно закрывается. Без закладки — «Скопировать команду» в консоль окна сайта. Открыл сайт не из приложения — всё приходит после `#` в адресе (на сервер в логи не попадает, из адреса сразу стирается), и Personal Computer спросит подтверждение.
   * **«Войти в окне приложения»** — страница входа chat.deepseek.com в браузере на сервере: вход по email или телефону, токен и отпечаток устройства забираются сами. Google здесь не пускает (см. Qwen) — для него «Войти через Google».
   * **«Токен вручную»** — папка с полем токена; команда (`copy(JSON.parse(localStorage.userToken).value)`) — в справке под «?» с кнопкой «Копировать». Подойдёт и весь `localStorage.userToken` (JSON `{"value": …}`), и с `Bearer`.
3. Карточка покажет «Подключён», чей это аккаунт и «Вход по паролю · токен обновляется сам» (или коротко, что не так — и кнопку «Пройти проверку», если дело в ней). Модель у сайта одна, поля модели нет; из настроек — только **«DeepThink»** (размышление вкл/выкл). Поиск в интернете самого DeepSeek выключен принудительно — у Personal Computer свои инструменты.

#### Запросы — как из вкладки браузера, проверка «я не робот» — в окне приложения

Перед chat.deepseek.com стоит защита AWS WAF (CloudFront). Запрос, не похожий на вкладку браузера, она встречает проверкой «я не робот». Раньше сервер так и выглядел: User-Agent `node`, без cookies и заголовков, которые браузер ставит сам. Теперь:

* **Один и тот же «браузер» у пользователя** (`deepseek.json` в его данных): User-Agent обычного Chrome (номер версии сам растёт вместе с настоящим Chrome) или твоего браузера, если он пришёл закладкой; подсказки `sec-ch-ua` — ровно как их собирает Chromium; `Accept-Language`; постоянный `x-device-id`; `sec-fetch-*` как у запроса со страницы сайта, `Origin` — только у POST, `Referer` — страница чата или входа.
* **Cookies сайта** — как у браузера: всё, что chat.deepseek.com выдал (`Set-Cookie`), возвращается ему; истёкшее выбрасывается; хранятся между перезапусками. Среди них и `aws-waf-token` — отметка о пройденной проверке.
* **Без спешки.** Запросы одного аккаунта — строго по очереди, с паузой 1,5–3 с и **не больше 10 ответов в минуту** (так часто человек не пишет даже в спешке). После проверки — «бережный режим» на 45 минут: паузы втрое длиннее, в минуту — вдвое меньше, название чата не придумывается (лишние запросы ни к чему).
* **Если проверка всё же случилась, задача не падает.** Защита отвечает `405` + `x-amzn-waf-action: captcha` (или `202` + `challenge`) — это распознаётся точно и отличается от блокировки адреса (`403 Request blocked` — там проверки нет, нужен прокси). Агент ставит задачу на паузу, в чате появляется карточка **«Нужна проверка» с кнопкой «Пройти проверку»**, в Telegram (если ты не в чате) — напоминание. Нажал — открывается **окно «Проверка DeepSeek»**: сервер открыл chat.deepseek.com в браузере на себе (тот же адрес, прокси, User-Agent и cookies, что у запросов модели), а в окне — живой экран этой страницы; нажатия, прокрутка (и пальцем на телефоне) и ввод с клавиатуры уходят туда. Проверку проходишь ты сам — Personal Computer её не решает и не обходит. Как только сайт снова пускает **запросы сервера** (это проверяется тем же запросом, что сайт делает перед сообщением), окно закрывается само, cookies переходят в «браузер» сервера, а задача **продолжается сама** — нажимать «Повторить» не нужно. Не пройдена — задача ждёт и сама пробует снова через 5, 15, 30 минут и дальше раз в час (защита часто отпускает сама); «Стоп» действует как обычно.
* **Браузер на сервере** нужен только для окна проверки (DeepSeek и Qwen) и входа в окне; запускается на время проверки и гаснет сам. Поставить: кнопка «Поставить браузер» в окне проверки (администратор, если у агента включён полный доступ) или на сервере **`sudo personalcomputer browser`** (системный Chromium, если он настоящий в репозитории дистрибутива, иначе — Chromium headless shell от Playwright в `/opt/personalcomputer/browser`, около 300 МБ); `sudo personalcomputer browser status | remove`. Свой путь — `PERSONALCOMPUTER_CHROME=/путь/к/chrome` в `/etc/personalcomputer/personalcomputer.env`. Браузер работает внутри изоляции службы и ходит только на сайт и его защиту (остальные адреса отклоняются ещё до запроса); профиль (cookies сайта) — у каждого пользователя свой, «Отключить» аккаунт стирает и его.

**Токен сайта со временем истекает** (по наблюдениям — через несколько часов или сутки): со входом по паролю Personal Computer войдёт заново сам; со входом через Google в чате появится просьба подключить заново — «Войти через Google» делает это за пару секунд.

* **История и чаты — как у Qwen.** Каждый чат Personal Computer — один чат на chat.deepseek.com (его видно и на сайте). Под ответом модели в истории лежит скрытая метка (id чата, id ответа, аккаунт, версия инструкции); следующий шаг продолжает тот же чат от этого ответа (`parent_message_id`) и отправляет **только новое**. Инструкция уходит один раз и повторно — только если изменилась. Чата больше нет (удалили на сайте, другой аккаунт, переключились с другого провайдера) — новый чат, и в него уходят инструкция и переписка (старое — сокращённо). Название чата модель придумывает во временном чате, который сразу удаляется.
* **Предел длины одного ответа.** У веб-чата DeepSeek ответ модели строго ограничен по длине (вместе с размышлениями): упёрся — сайт обрывает поток (статус `INCOMPLETE` или вовсе без «готово»). Personal Computer это замечает и **сам просит продолжить** в том же чате, а продолжение приклеивает к ответу (если модель повторила хвост — повтор срезается; «[END]» — продолжать нечего) — до 6 раз подряд. Пользователь видит один цельный ответ, а вызов инструмента, оборванный посреди JSON (например, `write_file` с большим файлом), дописывается и выполняется. Обрыв ловится и тогда, когда сайт написал «готово», а ответ кончился посреди блока вызова или длинный текст — посреди слова. Чтобы обрывов было меньше, модель знает про предел: большие файлы пишет частями (`write_file`, затем `edit_file`), длинное — по кускам.
* **Предел длины одного сообщения.** На слишком длинное сообщение (около 80 000 символов) сайт молча не отвечает. Поэтому одним сообщением уходит не больше 60 000 символов: длинные результаты команд сокращаются (начало и конец), в новом чате старая переписка ужимается, инструкция не режется никогда. Если сайт всё же не ответил — сообщение уходит ещё короче.
* **Защита запросов (PoW).** Каждый ответ модели и загрузка файла у DeepSeek требуют «доказательства работы»: сайт выдаёт задачу, и её решение уходит заголовком `x-ds-pow-response`. Алгоритм `DeepSeekHashV1` — SHA3-256 с Keccak-f[1600] без нулевого раунда — реализован прямо в сервере (без WASM и сторонних библиотек), сверен с официальным `sha3_wasm_bg.wasm` сайта; задача решается за доли секунды и не мешает серверу обслуживать остальных.
* **Бережно к аккаунту.** Одновременно аккаунт генерирует только один ответ, а за слишком частые запросы DeepSeek временно блокирует аккаунт («user is muted»). Поэтому запросы одного аккаунта идут строго по очереди, с небольшой случайной паузой (1,5–3 с; пока работают инструменты, пауза уже идёт) и не чаще 10 ответов в минуту. Если блокировка всё же случилась — в чате будет, **до какого времени** она действует, и Personal Computer не долбит сайт повторами. Это неофициальный способ пользоваться сайтом: ограничить аккаунт DeepSeek может в любой момент.
* **Файлы в чат.** Картинки (PNG, JPEG, GIF, WebP — до 5 за раз) и документы (PDF, Word, Excel, PowerPoint, TXT, MD, CSV, JSON — до 5), до 20 МБ, уходят в DeepSeek как с сайта: задача PoW → загрузка → сайт разбирает файл → файл прикладывается к сообщению. Картинку с сервера агент тоже может показать модели (`view_image`). Остальное (архивы, видео, код) лежит в `inbox/`, и агент открывает его своими инструментами. Каждый файл загружается один раз.
* **Ошибки — по-человечески:** «токен не подошёл или истёк», «неверный email (телефон) или пароль», «не узнал устройство», «временно ограничил аккаунт — до 15:40», «аккаунт заблокирован насовсем», «слишком частые запросы», «chat.deepseek.com не пустил запрос с этого сервера» (блокировка адреса — помогает прокси в настройках → Сервер). Проверка «я не робот» — не ошибка, а пауза с карточкой «Пройти проверку» (см. выше).
* Версию веб-клиента (заголовок `x-client-version`) можно задать `PERSONALCOMPUTER_DEEPSEEK_VERSION` в `/etc/personalcomputer/personalcomputer.env`, паузу между запросами (мс) — `PERSONALCOMPUTER_DEEPSEEK_GAP_MS`, ответов в минуту — `PERSONALCOMPUTER_DEEPSEEK_RPM` (0 — без предела), браузер для окна проверки — `PERSONALCOMPUTER_CHROME`.

### Kiro (kiro.dev) по аккаунту

Отдельный провайдер **«Kiro (kiro.dev)»**: модели [Kiro](https://kiro.dev) — среды разработки от Amazon (AWS) — по твоему аккаунту. У аккаунта каждый месяц бесплатные кредиты (новичкам — ещё бонус на первые недели); модели — Claude и другие, список зависит от плана. Сервер Personal Computer говорит с тем же API, что и сама Kiro IDE (AWS CodeWhisperer / Amazon Q Developer, `generateAssistantResponse`), — **без сторонних прокси и шлюзов** (включён прокси в настройках → Сервер — запросы идут через него).

1. Настройки → Модель → Провайдер «Kiro (kiro.dev)».
2. Нажми **«Войти через Google»** (или **GitHub**, или **«По email»** — аккаунт Kiro по почте, там же регистрация). Откроется окошко Kiro **в твоём браузере** — там ты уже вошёл в Google, ничего вводить не нужно: подтверди вход, и всё. Код на странице должен совпасть с кодом в карточке. Personal Computer сам получает доступ — без паролей, консоли и копирования токенов. С телефона окошко откроется вкладкой: войди там и вернись в приложение.
   * Как это устроено: вход «по коду устройства», как у Kiro CLI. Сервер просит у Kiro код (`prod.us-east-1.auth.desktop.kiro.dev/oauth/device/authorization`, провайдер `Google`, `Github` или `Cognito` — это вход по email) и, пока ты входишь, сам спрашивает Kiro, готово ли. Такой вход даёт профиль Kiro (`profileArn`), без которого новые версии Kiro запросы не принимают; поэтому кнопки AWS Builder ID нет (вход через AWS SSO профиля не даёт — остался только для «Токена вручную»). Пароль от Google или GitHub вводится только на их страницах. Поэтому Google тут не мешает: вход идёт в обычном браузере, а не в браузере на сервере.
   * **«Токен вручную»** — если стоит Kiro IDE: содержимое `~/.aws/sso/cache/kiro-auth-token.json` целиком или только `refreshToken` (`aor…`). Вход Builder ID из Kiro IDE — вместе с файлом клиента (clientId и clientSecret).
   * Ничего не теряется, если закрыть настройки посреди входа: сервер доведёт его сам, а при следующем открытии карточка покажет аккаунт (или снова код, если вход ещё идёт).
3. Карточка покажет, чей аккаунт (email), как вошёл и **сколько кредитов осталось**: месячные, бонус новичка (до какого числа), когда обновятся. В списке моделей у каждой — её расход кредитов («×1,3», «бесплатно»), под полем — видит ли модель картинки и сколько у неё контекста. Список — живой, от Kiro (`ListAvailableModels`): только то, что доступно твоему аккаунту.

**Доступ** живёт час и обновляется сам по refresh-токену — заранее (за 5 минут) и, если Kiro всё-таки сказал «истёк», посреди задачи незаметно для тебя. Refresh-токен (и секрет клиента Builder ID) лежат на сервере **зашифрованными** (AES-256-GCM, как пароль DeepSeek); «Отключить» стирает их. Отозвали вход — в чате просьба войти снова.

* **Инструменты — родные.** Kiro умеет вызовы функций: инструменты агента уходят схемами (`toolSpecification`), вызовы приходят `toolUseEvent`, результаты — `toolResults` с тем же id. Никаких текстовых договорённостей. Схемы чистятся под требования Kiro (без `additionalProperties` и пустого `required`), а история — строго пары «вызов → результат» (вызов без результата и результат без вызова Kiro не примет).
* **Размышление** — переключатель и **глубина** (низкая … максимальная), только у моделей, которые умеют: у Claude 5-го поколения — «адаптивное» с уровнем (`additionalModelRequestFields`), у моделей GPT — их `reasoning.effort`, у остальных Claude — договорённость Kiro `<thinking_mode>` (модель пишет `<thinking>…</thinking>` в начале ответа, а Personal Computer отделяет это от ответа — даже когда тег разорван между кадрами потока). Не принял модель уровень — повтор без него. Как и у других провайдеров, размышления не в чате, а в окне по долгому нажатию на компьютер.
* **История.** У API нет своей памяти, поэтому каждый шаг уходит вся переписка (инструкция — первым ходом), а один чат Personal Computer — один `conversationId` (Kiro кеширует общее начало). Переписка не влезла в модель — сам ужимаю длинные результаты команд и старые картинки и повторяю.
* **Картинки** — тем моделям, что их видят (`supportedInputTypes`), включая `view_image`; остальным — пометка, что картинка не передана. PDF Kiro не принимает: файл лежит на сервере, агент открывает его своими инструментами.
* **Поток** — AWS EventStream (двоичные кадры с CRC): текст идёт в чат сразу, как пишется; заполненность контекста — из `contextUsageEvent`.
* **Название чата** придумывает самая «дешёвая» модель каталога — кредиты почти не тратятся.
* **Ошибки — по-человечески:** «кредиты на этот месяц кончились», «модель недоступна на твоём плане», «вход истёк — войди снова»; перегрузку и «слишком много запросов» Personal Computer переживает сам (ждёт и повторяет, пока ты ничего не увидел).
* **Версия Kiro IDE.** Запросы идут «от имени» Kiro IDE, а старым версиям Kiro отвечает «This version of Kiro is no longer supported». Поэтому свежую версию сервер узнаёт там же, где сама Kiro IDE, — в её файле обновлений (`prod.download.desktop.kiro.dev/stable/metadata-…json`, раз в 12 часов), а если Kiro всё-таки сказал «устарела» — перепроверяет сразу и повторяет запрос. Свою версию можно задать `PERSONALCOMPUTER_KIRO_IDE_VERSION` в `/etc/personalcomputer/personalcomputer.env`.
* Это неофициальный способ пользоваться аккаунтом Kiro (так же устроены Kiro CLI и шлюзы вроде OmniRoute).

## Интерфейс

Тема выбирается в **Настройки → Компьютер → Внешний вид**. Три пиксельные ретро-темы — «Для девочек», «Для мальчиков», «Ламповая» — светлые и тёмные по настройке системы. Четвёртая — **«Современная»**:

* спокойный минимализм в духе Agent Pro: системный шрифт (SF Pro / Segoe UI / Roboto), тонкие линии вместо пиксельных рамок, мягкие тени, скругления, монохромные кнопки;
* **оформление** — «Как в системе», «Светлое» или «Тёмное» (переключатель появляется только у этой темы);
* чат — как в современных ассистентах: ответы без облачка во всю ширину колонки, твои сообщения — в серых «пузырях», поле ввода — одна «капсула» со скрепкой, микрофоном и кнопкой отправки;
* настройки — переключатель разделов-«таблетка», карточки групп, переключатели в стиле iOS, поля с аккуратной подсветкой фокуса;
* линейные значки вместо пиксельных (в том числе в проводнике: папки и листы с цветной меткой типа — IMG, PDF, ZIP…), код и терминал — на тёмном фоне с обычными цветами ANSI, без свечения ЭЛТ;
* **сам Personal Computer — тонкий алюминиевый ноутбук** вместо пиксельного моноблока (в трёх ретро-темах компьютер прежний): серебристый в светлом оформлении, «космос» в тёмном, с «чёлкой» камеры, клавиатурой, трекпадом, наклейкой-радугой и стикером на углу крышки. Нарисован в векторе по пикселям экрана, без пиксельной сетки:
  * **движения на пружинах** — прыжки с оттяжкой и сжатием при приземлении, мягкие наклоны, дрожь от испуга; **крышка — тоже пружина**: качается от толчков, во сне прикрывается (и спереди «дышит» огонёк сна), от испуга вздрагивает, от удивления распахивается, а при включении темы ноутбук открывается;
  * **лицо** — светящиеся глаза-«таблетки» и рот, собранные из параметров, поэтому выражения плавно перетекают одно в другое: моргание, взгляд за курсором, счастливые дуги, хмурые и грустные «веки», колечки от удивления, сердечки, звёздочки, румянец, слёзы, пот, очки «deal with it», кружка кофе;
  * **экран** — окна в духе современной системы: терминал с настоящей командой, поиск с настоящим запросом, текст ответа модели, код, план, графики, загрузка с процентом, змейка, понг и все секреты; программы сменяются плавно;
  * под «пальцами» подсвечиваются клавиши, экран подсвечивает клавиатуру своим цветом, а цвет экрана по-прежнему показывает заполненность контекста (зелёный → жёлтый → красный → гаснет); когда Personal Computer слушает, у камеры горит зелёный огонёк;
  * на экране загрузки и в окне обновления — тот же ноутбук; при «Уменьшить движение» в системе пружины и блики замирают.
* размер текста сообщений — тот же переключатель «Мелкий / Средний / Крупный», шрифт у темы свой.

Стили современной темы лежат отдельно — `server/public/theme-modern.css` (страница остаётся лёгкой), значки — небольшим скриптом в `index.html`, ноутбук — `server/public/pet-modern.js`: состояния, реплики, игры и секреты по-прежнему считает скрипт компьютера в `index.html`, а он каждый кадр отдаёт ноутбуку позу и что на экране.


* **Значки** нарисованы на одной сетке 10×10 и показываются в целое число раз крупнее — без размытия на любом экране. У кнопок есть подписи-подсказки, у вкладок и разделов настроек — значки рядом с названием.
* **Объём**: кнопки выпуклые (блик сверху, «ступенька» снизу, при нажатии проседают), поля ввода — утопленные, облачка и карточки отбрасывают жёсткую пиксельную тень.
* **Настройки** разложены по карточкам: «Внешний вид», «Звук и голос», «Приложение», «Подключение», «Возможности», «Шаги агента». Темы показаны в своих цветах — сразу видно, как будет выглядеть.
* **Анимации** плавные: облачко «выдувается» из хвостика, окна мягко открываются и закрываются, подсветка вкладок и переключателей переезжает к выбранному. Перерисованная история (после переподключения) не анимируется заново. Если в системе включено «Уменьшить движение», анимаций нет.
* **Значок приложения** — пиксельный ламповый компьютер с тёплым янтарным экраном (`icons/`, для Android — версия `maskable` с безопасными полями).

## История чатов

Кнопка с часами в шапке (или **Ctrl+K**) открывает окно со всеми разговорами.

* **Порядок** — по последнему сообщению: свежие сверху, разложены по группам «Сегодня», «Вчера», «Последние 7 дней», «Последние 30 дней», дальше — по месяцам. Справа — время, день недели или число; под названием — начало последнего сообщения.
* **Названия.** Пока чат новый, его название — начало первого сообщения. После второго ответа модель сама придумывает короткое название (2–5 слов) отдельным маленьким запросом без инструментов. Своё название — карандашом, двойным щелчком или F2; его модель уже не меняет.
* **Новый чат** — большая кнопка в окне или **Ctrl+Shift+O**. Пустой чат один: повторное нажатие не плодит пустых. `/new` в Telegram тоже начинает новый чат, прошлый остаётся в истории.
* **Поиск** — по названиям и по тексту сообщений, найденное подсвечено (с кусочком текста вокруг).
* **Удаление** — корзиной или Del, без лишних вопросов: внизу появляется «Чат удалён · Вернуть». Насовсем (вместе с его файлами в хранилище сервера) чат стирается через минуту. Если Personal Computer работает именно в этом чате, сначала спросит, остановить ли задачу.
* **Клавиатура**: ↑↓ — выбрать, Enter — открыть, F2 — переименовать, Del — удалить, Esc — сначала очистить поиск, потом закрыть; начал печатать в списке — это поиск. На телефоне карандаш и корзина видны всегда, клавиатура сама не выезжает.
* **Черновики.** Недописанное сообщение остаётся у своего чата: переключился и вернулся — текст на месте.
* **Один компьютер — одна задача.** Агент работает в одном чате (там же продолжает Telegram), а читать можно любой. У работающего чата в списке мигает «работаю»; в другом чате над полем ввода — «Работаю в чате «…»» с кнопками «Перейти» и «Стоп», а написанное там подождёт в поле, пока он не освободится.
* **Как хранится**: `users/<id>/chats.json` — список (название, время, превью), `users/<id>/chats/<id>.json` — сам разговор. Прежний единственный чат (`chat.json`) при обновлении становится первым в истории. Новая вкладка открывает чат, который открывали последним. API: `GET /api/chats[?q=]`, `POST /api/chats` (новый), `PATCH /api/chats/<id>` (`{title}`), `DELETE /api/chats/<id>`, `POST /api/chats/<id>/restore`; поток событий — `GET /api/stream?c=<id>`.

## Personal Computer в шапке

Вверху — обычная панель постоянной высоты (её больше не нужно и нельзя растягивать). В левом углу живёт сам **Personal Computer** — ламповый ретро-компьютер с клавиатурой и мышью, без комнаты вокруг; рядом — его имя и что он делает, справа — «История чатов», «Журнал» и «Настройки». На широком экране (от 720 px) в панели и вкладки «Чат», «Терминал», «Файлы»; на телефоне они, как раньше, внизу, под большим пальцем. Шагов работы и «печатает…» в чате нет — там только сообщения, файлы и ошибки.

* **Экран следует за агентом.** Команда (`run_command`) — терминал, где печатается настоящая команда и её итог; поиск — строка с настоящим запросом; чтение страницы — браузер; файлы — чтение, код или текст с именем файла в строке экрана; картинка, отправка файла (бумажный самолётик), навыки, MCP и Telegram — свои программы. Пока модель думает — пузырьки мыслей, дольше 10 с — песочные часы «жду модель». Пишет ответ — на экране печатается его текст. Готово — галочка и конфетти, ошибка модели — красный экран `ERROR 0X401`, «Стоп» — «Остановился». Движения прежние: подпрыгивает, покачивается, моргает, следит за курсором, зевает, чихает, щёлкает клавишами.
* **Облачко рядом с компьютером** говорит, что он делает прямо сейчас, — словами самой модели. У каждого инструмента (не только у команды) есть поле `action`: модель коротко объясняет шаг («Проверяю версию ядра», «Смотрю настройки nginx»), и это объяснение — со значком шага и итогом справа (`···` — идёт, `OK`, `СБОЙ`, `КОД 100`). Не объяснила — подпись от сервера («Читаю файл: nginx.conf»). Чтобы заскриптованные реплики не перебивали настоящие:
  * пока идёт работа, объяснение текущего шага закреплено и само не исчезает; внизу облачка — шаг, полоска и время задачи (когда до «Ограничения шагов» близко — сколько осталось);
  * реплики характера («Ещё чуть-чуть…», «Хи-хи, щекотно!», «Прочту после шага!») при закреплённом объяснении не заменяют его, а печатаются строчкой ниже и уходят сами;
  * новый шаг сменяет прошлое объяснение, но не раньше, чем его успели прочитать (быстрые шаги не мелькают — из ждущих остаётся самый свежий), а ждущая реплика поважнее не уступает очередь менее важной; ошибка показывается сразу;
  * в покое облачко — это реплики характера: приветствие по времени суток, советы, реакции на касание.
* **Журнал** (кнопка с песочными часами; на ней — сколько шагов в задаче, красная — если был сбой): каждый шаг с временем, длительностью и итогом — `OK`, `СБОЙ` или `КОД 100` с последней строкой вывода («E: Could not get lock …»); под шагом — команда или путь, по нажатию — целиком и кнопки «копировать» и «в терминал». Там же присланные файлы, ошибки, остановки и твои сообщения по ходу. Листаются последние 12 задач. Вкладка «Секреты» — найденные пасхалки.
* **Показатели сервера** CPU, память и температура (если есть датчик) — настоящие, с `GET /api/sys` раз в 5 с, только на очень широкой панели (от 1100 px).
* **Живой**: без дела включает заставку, потом засыпает — проснётся от касания. Нажми на него — погладить (только не слишком часто); наведи курсор и печатай — откроется его терминал (`help`, `snake`, `pong`, `time`…). 14 секретов — от Konami-кода до `rm -rf` (не бойся, это шутка). Пока он работает, игры его не отвлекают.
* **Размер** — около 70 пикселей на телефоне и около 78 на компьютере; масштаб кратен пикселям экрана — картинка чёткая.
* **Заполненность контекста**: по умолчанию экран светится по тому, сколько токенов занимает разговор, — зелёный до 100k, жёлтый до 200k, красный до 300k, дальше гаснет до чёрного (число — во всплывающей подсказке над компьютером). Сервер берёт `usage` из ответа модели, а если провайдер его не прислал — оценивает размер запроса сам. Чем полнее голова, тем чаще компьютер жалуется: «Голова забита…», «Не помню, что было в начале…», «Новый чат спасёт~»; в новом чате — снова зелёный и «Голова свежая!».
* **Темы**: свечение экрана — по контексту (по умолчанию), розовое, голубое или янтарное по теме, или своё (Настройки → Компьютер → «Свечение экрана»).
* **Звук** — только в настройках (Компьютер → «Звук и голос»): «8-битные звуки» — отклики интерфейса, «Звуки компьютера» — клавиатура, щелчки, игры и «бип-бип» облачка, ползунок громкости. Один 8-битный синтезатор на всё приложение (WebAudio, без файлов) с мягким фильтром «лампового» динамика и компрессором. Звук включается после первого касания (так требуют браузеры), в фоновой вкладке молчит, пока ответ читается вслух — притихает.
* **Бережно к батарее**: кадров в секунду сколько нужно (в работе 24, в покое 12, во сне и за окном настроек 8, в фоновой вкладке — ни одного); рисуется только маленький кадр вокруг компьютера. «Уменьшить движение» — без тряски и вспышек, 10 кадров в секунду.

| Сноски `[^1]`, источники `[1]: https://…`, `<details>`, картинки | значки-номера, раскрывашки, картинка или ссылка, если её не пускает CSP |

Модель знает об этих возможностях из системной подсказки и пользуется ими, когда это уместно: сравнение показывает таблицей, процесс — схемой. Ответ перерисовывается по мере печати, недописанная схема видна как код с подписью «рисую…».

## Telegram

Самый простой путь — попросить в чате: **«подключи Telegram»**. Personal Computer объяснит, как создать бота у [@BotFather](https://t.me/BotFather), примет токен (инструмент `telegram_connect`) и пришлёт одноразовую ссылку `t.me/твой_бот?start=…` — открой её и нажми «Старт». Токен сразу вычищается из истории чата и хранится только в защищённых данных сервера.

То же можно сделать в **Настройки → Сервер**.

В Telegram:
* обычное сообщение, фото или файл — новая задача (ход работы — в одном обновляемом сообщении); во время работы — дополнение или вопрос к текущей: Personal Computer прочтёт его между шагами, ответ по ходу дела и итог придут в Telegram;
* `/status`, `/stop`, `/now` (прочитать новые сообщения сейчас, не дожидаясь конца шага), `/new` (новый чат — прошлый остаётся в истории), `/web`, `/notify away|always|off`;
* когда задача из веба закончилась, а чат в браузере закрыт, Personal Computer пришлёт итог (режим `away`, по умолчанию).

Инструменты агента: `telegram_connect`, `telegram_status` (в т. ч. новая ссылка), `telegram_send`, `telegram_notify_mode`, `telegram_disconnect`. Бот отвечает только привязанному чату; остальным — «Это личный бот».

## Прокси (VLESS, VMess, Trojan, Shadowsocks, Hysteria 2)

Когда модель не работает из страны сервера (OpenAI, Anthropic, Gemini не пускают российские IP), Telegram тормозит, а GitHub недоступен — всё, что Personal Computer отправляет в интернет, можно пустить через свой прокси.

**Настройки → Сервер → «Прокси»** (менять может администратор, остальные видят, что включено):

1. вставь ключ — то, что выдал провайдер или панель (3x-ui, Marzban, Remnawave, Hiddify…), — и нажми **«Добавить»**. Можно сразу несколько ключей (по одному в строке) или **ссылку на подписку**;
2. включи **«Через прокси»** — Personal Computer сам проверит соединение и покажет, **куда выходит** (страна и IP), с какой задержкой и **отвечает ли модель** через этот сервер. Кнопка **«Проверить»** — то же в любой момент (для невыбранного сервера — на отдельном временном Xray, работающий прокси не трогается);
3. серверов может быть много: выбрать другой — нажать на него в списке.

Что понимает:

| Ключ | Пример | Как идёт |
|---|---|---|
| VLESS | `vless://uuid@host:443?security=reality&pbk=…&sid=…&flow=xtls-rprx-vision&type=tcp#Имя` | Xray |
| VMess | `vmess://base64(JSON)` (v2rayN), `vmess://uuid@host:port?…`, формат Shadowrocket | Xray |
| Trojan | `trojan://пароль@host:443?type=ws&path=…#Имя` | Xray |
| Shadowsocks | `ss://base64(метод:пароль)@host:port#Имя`, SS-2022, старый вид `ss://base64(…@host:port)` | Xray |
| Hysteria 2 | `hysteria2://auth@host:443?sni=…&obfs=salamander&obfs-password=…` (то же `hy2://`), смена портов `443,20000-30000` | Xray |
| SOCKS5 / HTTP(S) | `socks5://user:pass@host:1080`, `http://user:pass@host:3128`, `https://…` | Xray или напрямую из Node |
| Подписка | `https://sub.example.com/…` — список ключей строками или одним base64 | — |

* **Транспорты и шифрование**: TCP (в том числе с HTTP-маскировкой), WebSocket, gRPC, HTTPUpgrade, XHTTP (с `extra`); TLS (SNI, ALPN, отпечаток браузера `fp`, ECH, `pcs`/`vcn`), **Reality** (`pbk`, `sid`, `spx`, `pqv`), XTLS Vision, шифрование VLESS (`encryption=`). Чего Xray больше не умеет (транспорты HTTP/2 и QUIC, старый XTLS, mKCP, Shadowsocks с плагином и потоковыми шифрами), Personal Computer говорит сразу, а не после «не работает».
* **VLESS и Trojan без TLS к публичному серверу** Xray запрещает (такое соединение читается по пути) — нужен ключ с TLS или Reality.
* **`allowInsecure` / `insecure=1`.** Xray больше не умеет «не проверять сертификат». Personal Computer смотрит сертификат сам: настоящий — проверяется как обычно, самоподписанный — **закрепляется его отпечаток** (SHA-256). Сменил сервер сертификат — удали ключ и добавь заново. Для Hysteria 2 (UDP) без `pinSHA256=` в ключе это не всегда возможно — тогда понятная ошибка.
* **Подписка** обновляется сама раз в 12 часов (или как просит провайдер в `profile-update-interval`) и по кнопке «Обновить»; выбранный сервер остаётся выбранным. Видно название (`profile-title`), трафик и срок (`subscription-userinfo`). Скачивается напрямую, а если не вышло — через уже работающий прокси.

**Что идёт через прокси** — выбирается переключателями (по умолчанию — всё):

* **модель** — запросы к API (и обход Cloudflare через curl — тоже через прокси);
* **поиск и MCP-серверы** — HTTP-серверы MCP, поиск в интернете, установка навыков по ссылке;
* **Telegram** — бот;
* **команды агента и терминал** — переменные `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` (их понимают curl, wget, pip, npm, git, apt и большинство программ; локальные MCP-серверы получают их же). В терминале — в новых окнах и при новом подключении. Агент знает о прокси из подсказки (и что с `sudo` нужен `-E`);
* **проверка обновлений** — запросы к GitHub. Само обновление (`personalcomputer-update` от root) качает код напрямую.

**Всегда напрямую**: localhost, `127.x`, `10.x`, `172.16–31.x`, `192.168.x`, `100.64.x`, `169.254.x`, IPv6 `::1`/`fc00::/7`/`fe80::/10`, `*.local`, `*.lan`, `*.internal`, имена без точки (свой Ollama или LM Studio) — и **исключения** из настроек: домены (с поддоменами), `*.домен`, IP и подсети.

**Строгий режим.** Если прокси включён, а не работает (сервер прокси недоступен, ключ не подошёл), запросы не уходят напрямую — они падают с ошибкой «через прокси: …» и причиной из журнала Xray («сервер прокси не принимает соединения», «не отвечает (таймаут): его блокируют», «сертификат не прошёл проверку», ошибка Reality…). Так не утекает адрес сервера и не получается «молча работает, но не так». Выключить прокси — одна кнопка.

Как устроено:

* **Xray** (ядро [XTLS/Xray-core](https://github.com/XTLS/Xray-core) 26.9.9, ставит установщик в `/opt/personalcomputer/bin/xray`, сумма SHA-256 зашита) — дочерний процесс сервера Personal Computer: слушает только `127.0.0.1` (SOCKS5 и HTTP-прокси на одном порту, с паролем) и уходит на выбранный сервер. Конфиг (`/var/lib/personalcomputer/data/xray.json`, `0600`) перед запуском проверяется самим Xray — ключ с ошибкой не ломает работающий прокси. Упал — перезапускается (2, 5, 15, 30, 60 с). Частные сети Xray тоже отправляет напрямую — даже если программа агента не послушалась `NO_PROXY`.
* **Запросы сервера** идут через этот вход без сторонних библиотек: туннель SOCKS5 (имя хоста уходит прокси — DNS спрашивает он, а не сервер) и поверх него обычный HTTP/1.1 с keep-alive — ответ модели приходит потоком, как и без прокси.
* **Без Xray** (не скачался, старая установка) работают только `socks5://` и `http(s)://` — напрямую из Node. Для остальных ключей настройки подскажут обновиться: `sudo personalcomputer update` или кнопка «Обновить» поставит Xray.
* Ключи и адреса подписок хранятся в `/var/lib/personalcomputer/data/proxy.json` (`0600`) и **в браузер не возвращаются** — видно только имя, протокол и адрес сервера.

## Инструменты, MCP и навыки

Принцип: в памяти модели только то, что нужно сейчас, — но Personal Computer может сам подключить недостающее.

**Настройки → Инструменты** (применяется сразу). Всё разложено по папкам — «Встроенные» (по группам: Сервер, Файлы, Telegram, Расширения), «MCP-серверы», «Навыки»; при открытии видны только заголовки с итогом справа («4 из 9 · ≈1018 ток.»). Вкладка «Сервер» так же разбита на «Аккаунт» и «Telegram».

* **Встроенные инструменты** — включает и выключает **только пользователь**: у агента нет для этого инструмента, а в подсказке он видит, что выключенное трогать не может. Каждый можно выключить (`run_command`, `read_file`/`view_image`/`edit_file`/`write_file`, `send_file`, Telegram, управление расширениями). Выключенный инструмент не уходит в запросы к модели, его абзац исчезает из системной подсказки, а вызвать его модель не сможет, даже если «вспомнит». Рядом с каждым — примерный «вес» в токенах, сверху — сколько занимают все включённые.
* **MCP-серверы** — HTTP (адрес + заголовки, например `Authorization: Bearer …`) или локальные stdio (команда, например `npx -y @modelcontextprotocol/server-memory`, + переменные окружения). Можно выключить сервер целиком или отдельные его инструменты. Режим **«по запросу»** (по умолчанию): в подсказке одна строка с именем сервера, а его инструменты появляются, только когда модель вызовет `mcp_connect` (до конца этого чата).
* **Поиск в интернете** — тоже MCP-сервер, `search` ([Parallel Search](https://search.parallel.ai/mcp): `web_search`, `web_fetch`), только **предустановленный**: при первом запуске он уже есть в списке у каждого пользователя, включён и работает «всегда». Дальше это обычный сервер: его можно выключить, перевести «по запросу», выключить отдельные инструменты или удалить (удалённый сам не вернётся — подключить снова можно по тому же адресу). Служебные параметры Parallel (`session_id`, `model_name`) модель не видит — их подставляет сервер. Адрес по умолчанию меняет `PERSONALCOMPUTER_SEARCH_MCP` в `/etc/personalcomputer/personalcomputer.env` (пусто — без предустановленного поиска). Кто раньше выключал поиск в настройках модели, получит сервер выключенным. Удалили поиск или поменяли ему адрес — в «MCP-серверах» появится кнопка «Вернуть: Поиск в интернете» (агенту то же — `mcp_manage restore`). Ключ поиску не нужен; агент знает, что при ошибке поиска нельзя менять его адрес, а нужно сказать пользователю, в чём дело.
* **MCP за Cloudflare.** К HTTP-серверам MCP запросы идут так же, как к API модели: если Cloudflare не пускает Node.js, запрос повторяется через curl. В ошибке — начало ответа сервера (что он сказал на самом деле), а «проверь ключ» — только если ключ в заголовках есть.
* **Ключи в чате.** Сохранив ключ, сервер заменяет его в истории меткой `[секрет сохранён на сервере]`. Если модель передаст метку обратно (переподключит сервер с заголовками из истории), остаётся сохранённый ключ — метка его не затирает.
* **Навыки (skills)** — папки с `SKILL.md` в формате Anthropic Agent Skills. В памяти модели **только имена** включённых навыков; описания модель получает вызовом `skill` без имени, полный текст — `skill(имя)`, остальные файлы навыка (скрипты, справка) — через `run_command`, когда понадобятся. Установка по ссылке: папка или репозиторий GitHub (`https://github.com/anthropics/skills/tree/main/skills/pdf`), прямой URL на `SKILL.md`; или свой навык прямо в форме. Навыки лежат в `~/ИМЯ/skills/`.

Агент делает то же сам: «подключи MCP-сервер …», «установи навык …», «сделай навык из того, что мы сейчас делали» — инструменты `mcp_manage` и `skills_manage`. Ключи из таких сообщений сохраняются в защищённых данных сервера и вычищаются из истории чата. Не хочешь, чтобы агент менял набор расширений, — выключи эти два инструмента.

## Безопасность

У агента есть настоящий shell на сервере, поэтому защита построена в несколько слоёв:

* **Регистрация только по одноразовому приглашению** (первое печатает установщик). Каждый пользователь Personal Computer фактически получает терминал сервера — приглашай только тех, кому доверяешь.
* **Пароли** — scrypt с солью, сравнение за постоянное время; ограничение 10 ошибок за 15 минут на IP и на имя.
* **Сессии** — 32 случайных байта в cookie `__Host-…; HttpOnly; Secure; SameSite=Strict`, на сервере хранится только хеш. Изменяющие запросы требуют заголовок `X-PersonalComputer` и совпадения `Origin` (защита от CSRF).
* **Разделение привилегий.** Сервер (`personalcomputer`) хранит пароли, сессии, ключи API и токены ботов в `/var/lib/personalcomputer/data` (`0700`). Команды агента и терминал выполняются от **другого** пользователя — `personalcomputer-agent`, — которому эти данные недоступны (права + `InaccessiblePaths` в systemd). Утёкший через prompt injection shell не достанет ключи.
* **ttyd** не слушает сеть вообще — только unix-сокет, доступный группе `personalcomputer`, и принимает лишь запросы с заголовком, который ставит сервер **после проверки входа** (`--auth-header`). WebSocket — только с того же Origin (`-O` и проверка на сервере). Аргументы из URL не принимаются.
* **MCP и навыки.** Локальные MCP-серверы запускает исполнитель от имени `personalcomputer-agent` — с теми же правами, что и команды агента (и агент может прочитать их переменные окружения). Настройки MCP с ключами хранятся в данных сервера и в браузер не отдаются (видны только имена заголовков и переменных). Папки навыков сервер читает с проверкой пути, а пишет в них только через исполнитель.
* **Проводник** (вкладка «Файлы») работает через тот же исполнитель от имени `personalcomputer-agent` (подробнее — в «[Файлы (проводник)](#файлы-проводник)»): данных сервера он не видит, а содержимое файлов отдаёт с CSP `sandbox` и `nosniff` — HTML или SVG с сервера не исполнит скрипты на странице Personal Computer.
* **Файлы.** `read_file`, `view_image`, `edit_file` и `write_file` выполняет исполнитель от имени `personalcomputer-agent` — прав у них ровно столько же, сколько у команд агента. `send_file` отдаёт только обычные файлы из рабочей папки; путь проверяется по открытому дескриптору, поэтому симлинк на данные сервера не пройдёт. Загрузки пишутся только в новые файлы (`O_EXCL|O_NOFOLLOW`). Скачивание — `attachment` с `nosniff` и `sandbox`-CSP, только своему владельцу.
* **Страница** — строгий CSP: скрипты только свои и встроенные по SHA-256 (без `unsafe-inline`), `frame-ancestors 'none'`; HSTS.
* **Службы systemd** — `NoNewPrivileges`, `ProtectSystem`, `ProtectHome`, `PrivateTmp`, пустой набор capabilities у сервера; Caddy получает только `CAP_NET_BIND_SERVICE`, его admin-API выключен.
* **Загрузки** Node.js, ttyd, Caddy и Xray проверяются по контрольным суммам; версии ttyd, Caddy и Xray закреплены, суммы зашиты в установщик.
* **Прокси.** Ключи и подписки — в данных сервера (`0600`), в браузер не уходят; менять прокси может только администратор. Локальный вход Xray — только `127.0.0.1` и с паролем (его знают сервер и команды агента). Включённый, но неработающий прокси не пропускает запросы напрямую.
* **Обновление из браузера** — только для администратора. Сервер лишь кладёт файл-запрос; что и откуда ставить, root-служба `personalcomputer-update` решает сама по `/etc/personalcomputer/install.conf` (из запроса не читается ничего). Агент (`personalcomputer-agent`) положить запрос не может: данные сервера ему недоступны.
* Сервер Personal Computer **без npm-зависимостей** — нечему прилететь через цепочку поставок.

**Полный доступ агента (root)** снимает эту изоляцию целиком: агент сможет прочитать что угодно, включая данные сервера (см. «[Полный доступ агента](#полный-доступ-агента-root)»). Включить его может только администратор и только с паролем. Сам сервер Personal Computer root дать не может: он лишь просит root-службу, а та берёт из запроса одно слово — `on` или `off`.

## Разработка

```bash
cd server
npm run dev     # http://127.0.0.1:8787, данные в server/.dev, команды выполняются без отдельного пользователя
npm test        # тесты: вход, CSRF, агент, фоновая работа, остановка, файлы, файловые инструменты, проводник, перезапуск, Telegram, инструменты, MCP, навыки, обновления, доступ агента (root), быстрый старт (страница без образа Linux, поиск не держит агента), прокси (ключи, подписки, туннели, Xray)
```

Для первой регистрации в dev: `PERSONALCOMPUTER_DEV=1 PERSONALCOMPUTER_DATA=./.dev/data node personalcomputer.js invite`.

Прокси в dev: Xray ищется в `PERSONALCOMPUTER_XRAY`, `/opt/personalcomputer/bin/xray` и `PATH` (`PERSONALCOMPUTER_XRAY=none` — без него). Сквозной тест с настоящим Xray запускается, если он найден: `XRAY_BIN=/путь/к/xray npm test`.

Структура:

* `index.html`, `sw.js`, `manifest.webmanifest`, `icons/` — приложение: оформление, Personal Computer в верхней панели (`window.personalComputerRoom`, звуки `window.sfx`), чат, проводник (сервер добавляет `server/public/client.js` — вход, поток событий, настройки сервера, терминал). Экран загрузки — первым делом в `<body>` (`#boot`, `window.personalComputerBoot`): его шаги двигает `client.js`;
* `server/personalcomputer.js` — точка входа (`serve`, `runner`, `fileop` — файловая операция от root, `fsop`/`fsget`/`fsput` — то же для проводника, команды администратора);
* `server/lib/` — `server.js` (HTTP, SSE, CSP), `proxy.js` (прокси: ключи, Xray, маршруты, проверка, подписки), `proxylink.js` (разбор ключей и конфиг Xray), `tunnel.js` (fetch через SOCKS5 / HTTP CONNECT), `net.js` (запросы наружу, обход Cloudflare), `auth.js`, `agent.js` (фоновый агент), `runner.js` (исполнитель команд), `telegram.js`, `term.js` (прокси ttyd), `files.js`, `fsx.js` (проводник: список, поиск, копирование, архивы, чтение и загрузка), `rawio.js` (потоки «заголовок + байты» исполнителя), `mcp.js` (MCP-клиент: HTTP и stdio), `ext.js` (MCP-серверы, в том числе предустановленный поиск, и навыки пользователя), `update.js` (проверка обновлений и запрос на обновление), `access.js` (доступ агента: root вкл/выкл), `kiro.js` (провайдер Kiro: вход по коду устройства, обновление доступа, модели и кредиты, запрос с родными инструментами, поток AWS EventStream), `webchat.js` (общее для веб-чатов по токену: текстовый протокол инструментов, разбор ответа на лету, сборка истории, продолжение чатов по скрытой метке, вложения), `qwen.js` (провайдер Qwen: веб-API chat.qwen.ai), `deepseek.js` (провайдер DeepSeek: веб-API chat.deepseek.com, «браузер» — заголовки и cookies, вход по паролю, PoW DeepSeekHashV1, продолжение оборванных ответов), `browser.js` (Chromium на сервере по DevTools через pipe: экран, ввод, cookies, разрешённые адреса), `webid.js` (общий «браузер» веб-чатов: User-Agent, `sec-ch-ua`, cookies сайта, бережный темп), `webcheck.js` (окно проверки «я не робот» для DeepSeek и Qwen и входа в DeepSeek);
* `server/bin/personalcomputer-update` — обновление от root (по кнопке в настройках и `sudo personalcomputer update`);
* `server/bin/personalcomputer-access` — полный доступ агента от root (по кнопке в настройках, `sudo personalcomputer root on|off` и `install.sh --root`);
* `server/bin/personalcomputer-browser` — браузер для окна проверки и входа (DeepSeek, Qwen) (`sudo personalcomputer browser`, кнопка в окне проверки);
* `install.sh` — установщик.
